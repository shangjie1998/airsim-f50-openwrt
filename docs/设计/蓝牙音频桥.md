# 蓝牙耳机接打 AirSIM 电话：可行性方案记录（**只记录，未实施**）

状态：**不做**。留档给以后想试的人（或别的 AI）省一遍摸底。

## 1. 目标

让 F50 上的 AirSIM 通话走**蓝牙耳机**（耳机麦克风 + 耳机听筒），而不是手机端。

## 2. 已知约束（都是实测/查过的）

| 项 | 结论 |
|---|---|
| `/dev/audio_pipe_bthal` | **不存在**。Android 那条片内 vendor 音频通路（BT↔codec 直连）在 OpenWrt 上没有 |
| 内核 | `CONFIG_BT=y`、`CONFIG_BT_HCIUART=y`、`CONFIG_BT_HCIUART_H4=y` |
| 控制器 | BT 5.0，`SCO MTU 240:3`（SCO 在控制器层面是有的），无 ISO/LC3 → **LE Audio 不可能** |
| 设备工具 | 有 `btattach` / `bluetoothctl` / `hciconfig` / `btmgmt`；**没有** `btmon` / `pacat` / `arecord` / `aplay` |
| AirSIM 音频格式 | 8 kHz / mono / S16LE / 20 ms = 320 字节/帧 |
| 蓝牙 SCO 格式 | CVSD 8 kHz / mono / 16 bit —— **和 AirSIM 一模一样，理论上零重采样** |

SCO 这条路能不能走，取决于一件事：**这颗 WCN（展锐 marlin3）会不会把 SCO 音频交给 HCI**。
vendor 在 Android 上是把 SCO 音频直接塞给 `audio_pipe_bthal` → `ump9620` codec，HCI 上拿到的可能是空帧。
**这一条只有插上耳机实测才知道**，纸面推不出来。

## 3. 三段式架构（如果真要做）

```
      ┌────────── AirSIM agent（Go，arm64）──────────┐
      │  目前：写 hw:1,53 播放 / 读 hw:1,16 采集      │
      │  旁路：写 /run/airsim-bt/play.pcm             │
      │        读 /run/airsim-bt/cap.pcm              │
      └──────────────────┬───────────────────────────┘
                         │ 两条 FIFO（8k mono S16LE，320B/20ms）
      ┌──────────────────┴───────────────────────────┐
      │  airsim-bt-bridge（自写 arm64 小程序）        │
      │  play.pcm → SCO socket write                 │
      │  SCO socket read → cap.pcm                   │
      │  40 ms 抖动缓冲；SCO 若是 16k(mSBC) 则加降采样 │
      └──────────────────┬───────────────────────────┘
                         │ BTPROTO_SCO
      ┌──────────────────┴───────────────────────────┐
      │  BlueZ：耳机 pair / trust / connect           │
      │  HFP 建链后 SCO 才连得上（OpenWrt 无 oFono/PA）│
      └──────────────────────────────────────────────┘
```

要点：

1. **agent 侧改一处**：`AIRSIM_BT_BRIDGE=1` 时把 PCM 出口从 ALSA 换成一对 FIFO。
   必须在 `overlay/f50/` 打可开关的小补丁，默认仍走原路径（`hw:1,53` / `hw:1,16`）。
2. **桥本体**：Go 交叉编译（本机 `GOOS=linux GOARCH=arm64` 就能出），不依赖 alsa-lib。
   SCO socket 用 `syscall.Socket(AF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_SCO)` + `connect`。
3. **蓝牙侧**：耳机得先配对 + HFP 建链。没有 oFono/PulseAudio 时，直接开 SCO socket 连接
   **不一定成功**——这是第 4 节的判定实验要验的东西。

## 4. 开工前的判定实验（一次就能判死）

需要一个**蓝牙耳机**，然后在设备上：

```sh
# 1) 上电（rfkill 两个节点都要解，见 parts/docs/蓝牙.md）
btattach -B /dev/ttyBT0 -P h4 &
bluetoothctl power on
bluetoothctl --timeout 20 scan le        # hcitool lescan 会报 I/O error
bluetoothctl pair <MAC>; bluetoothctl trust <MAC>; bluetoothctl connect <MAC>

# 2) 用自写小程序试开 SCO socket 连耳机，看能不能收到非静音帧
#    收到 → 桥可行；连不上 / 全是零 → 判死，这条路放弃
```

判据：SCO socket `connect()` 成功 **且** 能从耳机侧读到有能量的 PCM（不是全 0）。
两者缺一，整条方案不必再做。

## 5. 为什么现在 "只记录不做"

- 没有蓝牙耳机可测，判定实验做不了，等于在纸上造桥；
- 即使 SCO 通，还要改 agent 的 PCM 出口（动的是**通话链路本身**，出问题就是打不了电话）；
- 设备当前连音频都没起（`/sys/module/audio_reserve/parameters/missing ≠ 0`，
  见 `docs/音频/重启丢音频.md`），先得把地基修稳。

## 6. 若将来要做，验收标准

- 默认（不设 `AIRSIM_BT_BRIDGE`）行为与现在完全一致，`/status` 的 `devices` 仍是 `hw:1,53`/`hw:1,16`
- 开了桥之后能完成一整通双向通话，`downlink_frames` / `uplink_frames` 都不为 0，`last_error` 为空
- 关掉开关能立刻回退，不需要改文件
