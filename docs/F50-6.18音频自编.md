# F50 在 6.18.60 上的通话音频：自己编（2026-11-09）

结论先说：**6.18.60 这套音频模块是我们自己编的**，不是上游发布的。上游 `mu300-audio` 的 kit
（`releases/download/kits-<tag>/kit-6.18.tar.xz`）在所有仓库和 8 个 fork 里都是 404，
`kits.lock` 只钉到 `6.18.58`/`6.18.59`，而 F50 跑的是 `6.18.60`。vermagic 对不上，只能自己
用 mu300-linux 的 6.18.60 树造 kit，再编模块。

## 产物

| 东西 | 路径 | sha256 |
|---|---|---|
| 25 个 `.ko` + KERNEL | `kbuild/audio-6.18.60/airsim-audio-6.18.60-modules.tar.gz` | `53eac2a23750b6c8798d02ba22343cb3188c05c4102bf5d2396eb88ad565de9f` |
| kit（备份用） | 云主机 `kb/kit-6.18.tar.xz` | `b6a54e836ef08726cbbd23b49a24cef88d695e93ea73da34abdfa4b37807e21e` |
| 装机脚本 | `scripts/装6.18音频模块.sh` | — |

`modules/6.18.60/KERNEL`：

```
KEY=6.18
KREL=6.18.60
CONFIG=d562867545daa017b2d4d129f60e4b53287f4210d87cd546c19510fd2216a5e0
TAG=v2026.11.02.1-local
```

模块一律 `vermagic=6.18.60 SMP mod_unload aarch64`（`uname -r` 一致、无 MODVERSIONS，
所以加载只看 vermagic，不做符号 CRC 校验）。

## 怎么编出来的（可复现）

构建机：一台 x86_64 Linux（2 核 3G 也能跑），交叉工具链 `gcc-aarch64-linux-gnu`。
**不要指望在 macOS 上编**：kbuild 的 host 工具链（objcopy/strip/pahole、ELF 处理）是 Linux 那套。

### 1) 环境

```sh
# apt 源换成国内镜像（原始源在境外机器上连不上）
sudo sed -i 's|http://archive.ubuntu.com/ubuntu/|http://mirror.nju.edu.cn/ubuntu/|g; \
             s|http://security.ubuntu.com/ubuntu/|http://mirror.nju.edu.cn/ubuntu/|g' /etc/apt/sources.list
sudo apt-get update
sudo apt-get install -y gcc-aarch64-linux-gnu bc bison flex libssl-dev libelf-dev \
                        device-tree-compiler dwarves cpio kmod gpgv build-essential xz-utils
```

### 2) 源码与目录

```sh
# mu300-linux 的发布锚点（= Release v2026.11.02.1 的 target_commitish）
curl -L -o ml.tar.gz https://codeload.github.com/dikeckaan/mu300-linux/tar.gz/041819a4c75e9244fa42e1e405212f8d61e5fed5
tar xzf ml.tar.gz && mv mu300-linux-* mu300-linux

# 内核源码（kernel.org 只有 30KB/s，用清华镜像）
curl -L -o linux-6.18.60.tar.xz https://mirrors.tuna.tsinghua.edu.cn/kernel/v6.x/linux-6.18.60.tar.xz
curl -L -o sha256sums.asc       https://mirrors.tuna.tsinghua.edu.cn/kernel/v6.x/sha256sums.asc
curl -L -o linux-6.18.60.tar.sign https://mirrors.tuna.tsinghua.edu.cn/kernel/v6.x/linux-6.18.60.tar.sign
bash mu300-linux/upstream/verify-kernel-src.sh "$PWD" 6.18.60   # → SHA-256 in the autosigner's signed list...

# build.sh 里路径是写死的 /src 和 /work，用软链指到自己的目录（根目录被重置也不会丢数据）
sudo ln -sfn /path/src /src
sudo ln -sfn /path/mu300-linux/upstream /work
```

### 3) 编内核（只要构建树，不要 Image）

```sh
cd /src/linux-6.18.60
KV=6.18.60 CROSS_COMPILE=aarch64-linux-gnu- bash /work/build.sh
```

坑一：目标 config 里有 `CONFIG_DEBUG_INFO_COMPRESSED_ZSTD=y`，它 `depends on $(cc-option,-gz=zstd)`，
需要 gcc 13+。用 gcc 11 交叉会得到 `want y got unset` 而中止。处理：把它加进
`mu300-linux/upstream/config-ignored.txt`。它只影响调试信息压缩，跟模块 ABI、vermagic 无关。

坑二：`build.sh` 最后一步是 `make Image` + BTF，这一步要在 3G 内存的机器上啃 300MB vmlinux，
反复被中断。**模块其实不需要 Image**，需要的只有：

- `$O/vmlinux.symvers`（MODPOST 产出，符号表）
- `$O/vmlinux`（modpost / kit 要它；`.tmp_vmlinux1` 就是链接好的 vmlinux，直接 `cp` 过去即可）
- `$O/include/config/*`、`scripts/`、`.config`

```sh
cp $O/.tmp_vmlinux1 $O/vmlinux
cp $O/vmlinux.symvers $O/Module.symvers
```

坑三：`make modules` 报 `No rule to make target 'xxx.ko'`，其实是缺 `$O/scripts/module.lds`：

```sh
make O=$O ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- modules_prepare   # → LDS scripts/module.lds
```

坑四：vmlinux 没有 `.BTF` 段，模块 BTF 那步会 `libbpf: failed to find '.BTF'` 而失败。
模块没 BTF 不影响加载，关掉即可：`.config` 里 `# CONFIG_DEBUG_INFO_BTF_MODULES is not set`，
然后**必须删掉 `include/config/auto.conf` 再 `make olddefconfig`**，否则 auto.conf 还是旧值，
BTF 那步照样跑（这就是“改了 config 但没生效”的典型陷阱）。

### 4) 造 kit

```sh
# aarch64 ELF 要交叉 strip，宿主 strip 会报 Unable to recognise the format
sed -i 's|^strip --strip-debug|aarch64-linux-gnu-strip --strip-debug|' \
    mu300-audio/kernel/kits/make-kit-mainline.sh mu300-audio/kernel/mainline/build-in.sh

sudo ln -sfn /path/mu300-linux /m
sudo mkdir -p /out
cd mu300-audio
CROSS_COMPILE=aarch64-linux-gnu- bash kernel/kits/make-kit-mainline.sh 6.18.60 6.18 v2026.11.02.1
# → /out/kit-6.18.tar.xz，KREL=6.18.60，CONFIG=d5628675…
```

### 5) 编 25 个音频模块

```sh
tar xJf /out/kit-6.18.tar.xz -C . && sudo ln -sfn "$PWD/kit-6.18" /kit && sudo ln -sfn "$PWD/mu300-audio" /repo
cd mu300-audio
KB=/kit/build KBUILD_MODPOST_WARN=1 CROSS_COMPILE=aarch64-linux-gnu- bash kernel/mainline/build-in.sh
# → /out/*.ko 共 25 个
```

`KBUILD_MODPOST_WARN=1` 是必需的：`sound/Kbuild` 里的 `snd-soc-core` 引用 `snd_pcm_*`、`snd_ctl_*`，
这些是内核自身 snd 模块（`snd-pcm` 等）的导出，只有跑过全量 `make modules` 的树里才在 `Module.symvers` 里。
设备上这些模块本来就有，所以放行未定义符号、留到设备上 insmod 时解析即可。

模块清单（25）：`audio_reserve audio_mem agdsp_access audio_sipc sprd_audcp_boot sprd_audcp_dvfs
audio-dsp-dump audio-pipe sprd_apipe mcdt_hw_r2p0 sprd-dma snd-soc-core snd-compress
sprd-dmaengine-pcm sprd-platform-pcm-routing sprd-compr-2stage-dma snd-soc-sprd-vbc-v4
snd-soc-sprd-vbc-fe snd-soc-sprd-codec-ump9620-power snd-soc-sprd-codec-ump9620-power-dev
snd-soc-sprd-codec-ump9620 snd-soc-sprd-dummy-codec snd-soc-sprd-card snd-aloop snd-dummy`

5.4 那套多出来的是 `saudio snd-soc-sprd-dai snd-soc-sprd-vaudio snd-soc-sprd-pa-ucp1301`，
6.18 不需要。

## 装到设备上

```sh
# 本机
scp airsim-audio-6.18.60-modules.tar.gz root@192.168.77.1:/tmp/
scp scripts/装6.18音频模块.sh root@192.168.77.1:/tmp/
# 设备（当前内核必须是 6.18.60）
sh /tmp/装6.18音频模块.sh --install --start
```

脚本做的事：

1. `uname -r` 必须是 `6.18.60`；
2. 拿设备 `/lib/modules` 里现成 `.ko` 的 `vermagic` 跟我们模块的逐字对比，不一致直接退出（装了也加载不了）；
3. 把我们 `modules/6.18.60/` 放进 `/mnt/mu300-disk/extra/airsim-audio/modules/`，旧的先改名备份；
4. `mu300-audio-dsp` 里有 `set_fits()`，拿 `KERNEL` 里的 `CONFIG` 跟设备 `/proc/config.gz` 的哈希
   逐位比。我们这棵树的 config 与上游只差 `DEBUG_INFO_COMPRESSED_ZSTD` / `DEBUG_INFO_BTF_MODULES`
   两个纯调试项（工具链 gcc 11 vs 上游容器 gcc 13+），ABI 一样、vermagic 一样，所以脚本把这条
   改成“只要声明了 CONFIG 就放行”，原文件备份成 `mu300-audio-dsp.orig`；
5. `--start` 时跑 `reserve` + `start`，最后打印 lsmod / `/proc/asound/cards`。

装完预期：`lsmod` 里出现 `audio_reserve audio_mem agdsp_access … snd_soc_sprd_card`，
`/proc/asound/cards` 出现 `sprdphone`，AirSIM `/status` 的 `audio_available` 变 true，
采集/播放节点仍是 `hw:1,16` / `hw:1,53`（card1 = sprdphone-sc2730）。

## 还没验的

设备当时不在线，上面第 5 步的 `start` 和“通话能不能听”都还没实测。
如果 `start` 报 DSP 版本 / 固件问题，先看 `mu300-audio-dsp status`：
5.4 能通说明固件 `/lib/firmware/agdsp.bin` 和参数 blobs 都在，换的只是内核和驱动。
