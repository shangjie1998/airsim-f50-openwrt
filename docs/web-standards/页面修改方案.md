## 三、修改方案

### A 组 · 全局一次改（覆盖所有页）

**A1 字号改 rem（P1）**

`ui.css` 里 7 个 `--as-fs-*` token 的值由 px 改 rem，新增 `html{font-size:16px}` 作基准；15 处硬写 px 的业务性小字号并入 token，装饰性数字（如 30px 号码）保留。

- 收益：iPad 系统字号调大后全站跟着放大。
- 代价：全站观感一次性变化，必须逐页真机截图复核；只动 `ui.css`，不碰逻辑。

**A2 统一字段封装（P0，解决多个页面）**

`ui.js` 增加 `field(label, node, help)`，行为对齐 `call.js:46` 的现成范式：生成 `<label for>`、给控件补 `id`、有 help 时加 `aria-describedby`。

- 收益：一处封装，`net.js` / `audio.js` / `settings.js` 全部受益；以后新页面不会再漏。
- 代价：要改这三页的调用点，改动集中在渲染处，不动业务逻辑。

**A3 状态播报推广（P1）**

现有 `as-feedback`（已带 `role="status" aria-live="polite"`）只在 connect / maintenance / overview / sms 用，推广到 `net / audio / call / bluetooth` 的状态文本。

- 收益：读屏能播报「扫描中 / 连上了 / 失败了 / 保存成功」。
- 代价：低，替换文本容器即可。

## 八、第四遍：真机实测抓到两处新问题

前三遍全是静态扫描，看完代码就下结论。真机上跑了一遍，抓出两个谁也看不出、只有跑起来才现形的问题：

### 8.1 `glass.js` 里藏着第二套 px 字号体系（漏项，已修）

`glass.js` 自己定义了一套 `--fs-title:34px / --fs-body:15px / --fs-cap:13px / --fs-note:12px`，并通过 `<style>` 注入页面。注入的样式排在 `ui.css` 之后，同优先级下后者生效——**我改 `ui.css` 的 rem 全部被它压回去了**。

实测证据：把根字号从 16px 调到 20px，正文 `.as-root` 从 15px 涨到 18.75px（rem 生效），但说明文字 `.as-caption` 一动不动停在 13px。

- 前三遍为什么没抓到：两套 token 名字不同（`--as-fs-*` vs `--fs-*`），grep `--as-fs` 时完全看不见另一半。
- 修法：`glass.js` 的 `--fs-*` 全部改成引用 `ui.css` 的 `--as-fs-*`（带 rem 兜底），行高由 px 改成无单位倍数。字号从此只有一处真源。
- 验证：根字号 20px 时，说明文字 13px → 16.25px、标题 22px → 27.5px，全部跟随。

### 8.2 自绘开关没有可访问名称（漏项，已修）

`glass.switch()` 生成的按钮只有圆点、没有文字。旁边那行「启用来电通知 / Wi-Fi 上网 / 允许从 Wi-Fi 打开管理页」是画在行里的兄弟元素，跟按钮没有任何关联。

实测：`button[role=switch]` 的 `textContent` 是空字符串，`aria-label` 为 null。读屏只会念「开关，已打开」。

- 修法：`glass.switch(on, handler, label)` 增加第三个参数，挂成 `aria-label`；三个调用点（`call.js` 1 处、`net.js` 2 处）补上名称。
- 顺带确认：`call.js` 那个隐藏 checkbox（`as-call-enabled`，`display:none`）只是真值源，读屏本来就不读，不算缺陷。

## 九、教训

> 前端改字号这类事，代码里搜干净不算完。**同一个页面可能有两套样式体系叠加，只有真机量一次计算值才暴露。**
> 这也印证了「评估三遍不动代码、有出入再上真机」这条规矩的顺序是先静态三遍、再实测；但实测不是可选项——本轮两处漏项全是实测抓的。

## 十、第五处：卡片区从 `columns` 换成 `grid`

iPad 截图暴露出蓝牙页「本机蓝牙」和「已配对设备」之间空了近 150px，整页像断成两截。

**根因**：`.as-layout` 用的是 CSS `columns`（多列布局）。`columns` 是给连续正文分栏设计的，它会做列高平衡：卡片高度不齐时，短的那列底部就留一大片空白；再叠上 `break-inside:avoid` 和 `column-span:all`，Safari 还会吞卡、跳列——原作者注释里已经写过「iPad 的 Safari 在多列下会吞卡、跳列」，之前是靠「≤1200px 强制单列」绕开的，属于用断点盖住症状。

**改法**：`.as-layout` 改 `display:grid`（`repeat(auto-fill, minmax(min(100%,300px),1fr))`），`.as-wide` 用 `grid-column:1/-1`，单列门槛从 1200 抬到 1400（13 寸以下和触屏一律单列）。grid 按行列摆格子，卡片顺序固定，只在同一行的空位上可能留白，不会再出现「半页空白」。

顺带补一条 `.as-layout>*:empty{display:none}`，蓝牙页那个等到扫描才填内容的 `pending` 空盒子不再占一条 18px 的缝。

**验证**（用同源 iframe 卡到指定宽度实测，绕开浏览器视口限制）：

| 宽度 | 列数 | 卡片数 | 相邻最大间隙 |
|---|---|---|---|
| 560 | 1 | 5~7 | 18px |
| 1030 | 1 | 5~7 | 18px |
| 1440 | 3 | 5 | 同行留白（桌面可接受） |

九页（overview / connect / net / call / sms / maintenance / settings / bluetooth / audio）全部无横向溢出，单列下间隙一致 18px。

## 十一、给 iPad 的提醒

`ui.js` 是 JS 模块，浏览器会按 `?v=` 缓存它；`ui.css` 的版本号写死在 `ui.js` 里的 `CSSVERSION`。所以**改了样式必须让 iPad 硬刷一次**（`Cmd+Shift+R` 或关掉标签重开），否则旧 `ui.js` 会继续引用旧版 `ui.css`，改了也看不见。这是这套资源加载方式的老毛病，不是这次的 bug。

## 十二、第六轮自查：三处「信息重复」和一处「该消失没消失」

用同源 iframe 卡到 380 / 560 / 1030 三档宽度，九页逐页量了几何、溢出、命中区、文字截断，顺手截图肉眼过了一遍。数据层面是干净的：**没有横向溢出、没有子元素溢出卡片、没有文字被截断、卡片宽度一致**。但图上抓出四个问题，全是「说得太多」和「露得太多」。

**1. 窄屏顶部「蓝牙 蓝牙」**

`.as-menu-narrow`（窄屏用的导航）里同时放了一个 `.as-menu-current` 显示当前页名，和一个 `<select>` 下拉，而下拉选中的也是同一页。380px 下两个「蓝牙」并排，像出了 bug。

改法：删掉 `.as-menu-current`，窄屏只留下拉。下拉自带 `aria-label` 和选中项，语义不缺。顺带清掉 `activeTitle` 这个只被它消费的变量。

**2. 「附近的设备」说明重复**

卡片抬头已经写了「点「扫描」找周围能连的设备（15 秒）。已配对的点「连接」，没配过的点「配对」。」，里面的 `nearBox` 初始又塞了一句「点「扫描」找周围能连的设备（15 秒）。」——同一句在一张卡里出现两遍，中间隔着一个按钮。

改法：`nearBox` 初始留空，内容交给 `renderNearby()` 填。没扫过的状态由抬头那句话引导，够了。

**3. 主题页脚的构建信息露在页面最底下**

每页最底有一条 `Powered by LuCI (HEAD detached at 128a7812) branch (26.180.75667-128a781) / OpenWrt 25.12.5 (r33051-f5dae5ece4)`。这是开发构建的版本串，放在用户界面上既难看，也把内部构建号全抖搂出去了。

改法：`body.as-menu-on footer{display:none!important}`。只收主题的 `<footer>` 标签，我们自己那个 `.as-footer` 是 `div`，不受影响。

**4. 刷新按钮偏小（暂不改）**

`↻` 那个按钮实测 28×28，开关 56×32、复选框 19×19。触屏推荐 ≥44px，但这些都是次要操作，卡片里位置也稳定，加大会顶乱排版。记在这，等真有人嫌小再说。

## 十三、一个必须要知道的坑：热更新改 JS，不硬刷等于没改

这轮改完传到设备，浏览器里看到的**还是旧版**。查下来：

- 服务端文件是对的（`md5sum` 与本地逐字节一致，`wget` 拉回来也对）
- 但页面里加载的是 `ui.js?v=26.180.75667~128a781-1794331997`

那个 `?v=` 不是我们控制的，是 LuCI 按**主题版本 + 一个固定时间戳**拼出来的，改文件内容、`touch` 目录、重启 `uhttpd` 都不动它。所以浏览器一直命中 HTTP 缓存，**`ui.js` 和 `bluetooth.js` 被缓存锁死**，`ui.css` 因为 `CSSVERSION` 变了才会重新拉。

结论：
- 改 CSS → 升 `CSSVERSION` 就能自动生效
- 改 JS → **必须硬刷**（iPad 上长按刷新按钮选「硬刷新」，或电脑 `Cmd+Shift+R`）
- 设备重启会换掉那个时间戳，缓存跟着全破，所以「重启后正常了」不是玄学

正式发版打包时也一样：安装包装的是新文件，但浏览器缓存还是认 `?v=`，用户首次打开仍可能看到旧界面。这可能得在打包流程里加一步「安装后提示用户硬刷」，或者换成给脚本 URL 加内容哈希——这条先记着，没动。
