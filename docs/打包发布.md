# 打包与发布

> 造包全在 `build/`，配件在 `parts/`，设备侧一次性脚本在 `ops/`。三者互不越界。

## 一、三条出包线

| 产物 | 谁打 | 命令 | 名字 |
|---|---|---|---|
| 主包（插件，不绑内核） | `build/make-package.sh` | `sh build/make-package.sh` | `airsim-f50-<VER>.tar.gz`，`<VER>` 形如 `0.1.0.26-r23-any` |
| 音频配件包（按内核） | `parts/audio/make-opt.sh` | `sh parts/audio/make-opt.sh <KREL>+<tag>` | `airsim-f50-audio-opt-<ver>-k<KREL>+….tar.gz` |
| 内核算子（自编 ko 用） | `parts/audio/build-krel.sh` | `sh parts/audio/build-krel.sh --krel <KREL> --tree <内核源码树> --tag <tag>` | 落 `parts/audio/payload/<KREL>+<tag>/` |

## 二、主包发布六步

```sh
# 1) 升号（只动 N，不动主版本与 rNN）—— 一次写 VERSION 与 AGENT-VERSION
sh build/bump-version.sh 22 r23 any

# 2) 打包。脚本里串了两道闸：
#    闸一 check-consistency.py：源码里的版本号彼此对不上就拒绝出包
#    闸二 check-package.py：出包后解包核对 TAG/FILE/ready/1MB 文案 + usr/libexec 白名单
sh build/make-package.sh --build

# 3) 闸二已经自检过了，这里只看一眼体积与哈希
ls -l dist/airsim-f50-<VER>.tar.gz && cat dist/airsim-f50-<VER>.tar.gz.sha256

# 4) 上设备（先校验 sha，再装）
scp dist/airsim-f50-<VER>.tar.gz root@192.168.77.1:/mnt/mu300-disk/pkg/
#   设备上：sha256sum <包>；cd /tmp && mkdir p && tar -xzf <包> -C p && sh p/*/install.sh

# 5) 发 Release（附件同名；正文写清内核矩阵与本版改动）

# 6) 上传后跑闸三回读线上（别省，就栽过「本地打了、传上去是旧的」）
python3 build/tools/check-release.py --tag <tag> dist/airsim-f50-<VER>.tar.gz
```

## 二点五、音频配件包出包

```sh
cd parts/audio && sh make-opt.sh          # 末尾自动跑闸二
# 上传后：
python3 build/tools/check-release.py --tag audio-opt-v<ver> \
  dist/airsim-f50-audio-opt-<ver>-k6.18.60+7.3.1.tar.gz \
  parts/audio/thirdparty/mu300-audio-5.4.tar.gz
```

## 三、必须守的几条

1. **`overlay/f50/**` 与 `src/**` 不要改名** —— `.github/workflows/build-plugin.yml` 按这两个路径触发与编译，动了 CI 就哑。
2. **包内文件权限**：页面 / JSON 必须 `644`，可执行脚本 `755`。权限 600 会让 uhttpd 报
   `HTTP error 403 while loading class file`，页面直接打不开。
3. **升级号不覆盖老 Release**：新版本新 tag，旧资产原样留着。
4. **发布前必须真机装一遍**，`install.sh` 的退出码与打印内容都要核 —— 内核提示文案错了比不提示更坑。
5. **升号之后必须先重编再打包**：`VERSION` 是每次现读的，`out/f50` 里的二进制却可以是几天前编的。
   只升号不重编，会打出「新标签 + 旧内容」，设备上 `ubus call airsim status` 与 `VERSION` 对不上。
   用 `sh build/make-package.sh --build`（会先跑 `overlay/f50/build.sh`），一致性闸的第 5 项也会拦。
6. **macOS 打包注意**：`bsdtar` 会塞 `._*` 影子文件，安装脚本按"顶层只有一个目录"判结构时会误判；
   `build/make-package.sh` 与 `parts/audio/make-opt.sh` 都已加 `COPYFILE_DISABLE=1 --no-xattrs --no-mac-metadata`，
   别手工 `tar` 替代。主包之前处理过，配件包是这轮才补上的（少了约 200 个影子文件）。
7. **测试 / 调试脚本不许进交付包**：`usr/libexec/` 下有白名单（`check-package.py` 的 `LIBEXEC_ALLOWED`），
   多出任何不在名单里的脚本，闸二直接失败。新加功能脚本要顺手进白名单；测试工具放 `build/tools/`。
   原因见复盘 R11：自测钩子第一件事是 `rm -rf` 模块目录，混进用户手里等于留了个自毁按钮。
8. **上传后必须跑闸三**。闸二只证明「包里的东西是对的」，闸三才证明「线上那份就是这个包」。
   这轮就出过「本地打好了、传上去是上一次的」——页面点安装下回来的是旧包，肉眼完全看不出来。

## 四、发 Release 的最小 curl（PAT 走 header）

```sh
TOKEN="${GITHUB_PAT:?先 export GITHUB_PAT}"   # 令牌只走环境变量，不进仓库
# 建 Release
curl -sX POST -H "Authorization: Bearer $TOKEN" -H "Accept: application/vnd.github+json" \
  -d '{"tag_name":"v0.1.0.26-r23-any","name":"v0.1.0.26-r23-any","body":"…"}' \
  https://api.github.com/repos/shangjie1998/airsim-f50-openwrt/releases
# 传附件（走 uploads.github.com）
curl -sX POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/octet-stream" \
  --data-binary @dist/airsim-f50-0.1.0.26-r23-any.tar.gz \
  "https://uploads.github.com/repos/shangjie1998/airsim-f50-openwrt/releases/<id>/assets?name=airsim-f50-0.1.0.26-r23-any.tar.gz"
```

## 五、发完怎么核

| 核什么 | 怎么核 |
|---|---|
| 远端真的收到提交了 | `git fetch tmp main && git log --oneline -1 tmp/main`（别只看本地） |
| 附件真传上去了 | 资产列表里 `size` 与本地一致、`state=uploaded` |
| 包内容没被结构改动搞坏 | 下回来解压，跟上一个已发布包做 `diff -r`，要求**清单与内容全一致**（只有 tar 时间戳会差） |
| 设备侧生效 | `cat /usr/lib/airsim/VERSION`、`ubus list \| grep -c airsim`（期望 8）、`/etc/init.d/airsim status` |

## 六、回退

- 提交：`git revert <commit>`（结构类改动建议整笔回退，别半截）
- 包：装回上一版 tar.gz 即可（`install.sh` 是覆盖式，不动内核与分区）
- 内核：`mu300-update rollback-boot`（要求 `prev.*` 还在），否则重新喂包
