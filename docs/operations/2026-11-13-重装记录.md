## 第 4 步：排查「蓝牙配件显示已安装」与「蓝牙页点不进去」

现象（用户真机截图）：
- 维护页「可选配件」里，蓝牙配件包 `bt-opt v1.0.3` 显示 **已安装**（绿点）
- 音频模块 `audio-opt v1.0.3` 显示 **内核不匹配**（红点），并列出 5.4.254 / 6.18.60 / 6.18.60.bak×2 / 7.3.1
- 蓝牙页面点进去卡住

### 定位过程

设备实测：

| 检查项 | 结果 |
|---|---|
| `/lib/modules/6.18.54/` 里的蓝牙驱动 | `sprdbt_tty.ko`、`wcn_bsp.ko` **都在** |
| `/etc/init.d/sprdbluetooth` | **不存在** |
| `/usr/sbin/sprd-bt-attach.sh` | **不存在** |
| `/usr/bin/bluetoothd`、`/usr/bin/btattach` | **存在**（固件自带） |
| `hciconfig hci0` 裸调用耗时 | 0 秒 |

两个问题：

**(1) 探针误判「已安装」**

原判定：

```sh
installed=0
[ -x /usr/bin/bluetoothd ] && [ -x /usr/bin/btattach ] && installed=1
```

只查两个客户端二进制。这俩是固件自带的，于是配件一个没装也报「已安装」——页面会骗人去点扫描，实际扫不出东西。

**(2) 蓝牙页卡住 30 秒**

`bt_state` 里 `hciconfig hci0`（0 秒，不卡）之后还有一个兜底：

```sh
if [ -z "$nm" ] && command -v bluetoothctl >/dev/null 2>&1; then
    nm=$(bluetoothctl show 2>/dev/null | ...)
fi
```

没有 hci0、没有 bluetoothd 时，`bluetoothctl` 会死等 D-Bus 直到 30 秒兜底，ubus 正好也是 30 秒超时 → 整页卡死。

### 修复

1. `btopt_probe` 的 `installed` 改成按整条链判定，四个条件缺一不可：
   - `/usr/bin/bluetoothd`
   - `/usr/bin/btattach`
   - `/usr/sbin/sprd-bt-attach.sh`
   - `/etc/init.d/sprdbluetooth`
2. `bt_state` 里所有 `hciconfig` / `bluetoothctl` 调用都先判 `[ -d "$HCI" ]`；`bluetoothctl` 另加「bluetoothd 在跑」前置条件，并套 `timeout 3`

实测（热更后 rpcd 重启）：

| 项 | 修复前 | 修复后 |
|---|---|---|
| `ubus call airsim-bt bt_get` | 30 秒超时 | **0 秒**返回 |
| `bt_opt_probe.installed` | true（误） | **false**（准） |
| `bt_opt_probe` 其它字段 | — | `kernel=6.18.54`、`want_kernel=6.18.60`、`native_bt=true`、`kernel_ok=true` |

### 回答用户的两个疑问

- **什么时候装的蓝牙配件包？** 从来没装过。「已安装」是探针误判，前面那节已经说清判定条件。
- **默认应该啥也没有吗？** 是。全新固件上蓝牙配件应该是「未安装」，点了才走 下载 → 校验 → 解压 → 装驱动 这条链，进度就显示在「可选配件」那张卡片里（`开始装了` 下面会随状态走）。

## 第 5 步：蓝牙配件包按内核选，不再钉死一个版本

用户指出：**“配件包按内核编二进制：6.18.60 7.3.1。内核对不上的要换配件包，不是硬装。蓝牙这个也要有类似的判断和提示，我现在只编译了 6.18.60 的，别写死，得有音频这种判断提示。”**

### 原来错在哪

`rpcd/airsim-bt` 顶部是硬编码：

```sh
BT_OPT_FILE=airsim-f50-bt-opt-1.0.3-k6.18.60.tar.gz
BT_OPT_KVER=6.18.60
```

本机 6.18.54，等于永远指向一个不存在的包；`kernel_ok` 又掺了 `native_bt` 豁免，把「驱动自带」误当成「配件包能用」，页面于是既不报不匹配、也不拦安装。

### 改法（照音频那套）

**后端 `rpcd/airsim-bt`**

1. 常量去掉内核：

```sh
BT_OPT_TAG=bt-opt-v1.0.3
BT_OPT_VER=1.0.3
BT_OPT_KERNELS='6.18.60 7.3.1'   # 出过包的内核，新包会自动补进来
```

2. 新增 `bt_opt_avail_krels()`：已知清单 + Release 检查缓存里的文件名 + 本地扩展目录里躺的包，三处合并去重，输出 `6.18.60 7.3.1` 这样的列表。

3. `btopt_probe` 的 `kernel_ok` 只问一件事 —— 有没有对着这个内核编的包：

```sh
case " $avail " in *" $kver "*) kernel_ok=1 ;; esac
```

（删掉了 `native_bt` 豁免：驱动自带只说明「不装也行」，不等于「这个内核的包存在」。）

4. `file` 和 `url` 按当前内核现算：`airsim-f50-bt-opt-1.0.3-k$(uname -r).tar.gz`

5. `btopt_install` 开装前先校验内核，不在覆盖范围直接拒绝：

```sh
error: "本机内核 6.18.54，现有配件包只对 6.18.60 7.3.1 出过；驱动对不上，硬装只会把蓝牙装死。"
```

**安装器 `usr/libexec/airsim-btopt-install`**

```sh
KVER=$(uname -r)
FILE=${AIRSIM_OPT_FILE:-airsim-f50-bt-opt-1.0.3-k$KVER.tar.gz}
```

**前端 `maintenance.js`**：chip 从两态变四态

| 条件 | chip | 颜色 | 按钮 |
|---|---|---|---|
| 正在装 | 正在装 | 中性 | 禁用 |
| 已装齐 | 已安装 | 绿 | 可用 |
| 可装但没装 | 未安装 | 中性 | 可用 |
| 没有对应内核的包 | **内核不匹配** | **红** | **禁用** |

文案：`本机内核 6.18.54，现有配件包只对 6.18.60 7.3.1 出过。驱动模块必须跟内核一致，对不上装不了；等这个内核的包出来，或者把系统切到上面列出的内核。`

### 实测

```
$ ubus call airsim-bt bt_opt_probe
kernel: 6.18.54
want_kernel: "6.18.60 7.3.1"
native_bt: true
kernel_ok: false
file: airsim-f50-bt-opt-1.0.3-k6.18.54.tar.gz

$ ubus call airsim-bt bt_opt_install
ok: false
error: 本机内核 6.18.54，现有配件包只对 6.18.60 7.3.1 出过；驱动对不上，硬装只会把蓝牙装死。
```

页面：chip 红点「内核不匹配」，「安装蓝牙」按钮 `disabled=true`，说明文字列出 `6.18.60 7.3.1`。

以后出了 6.18.54 的包：把包传到本地扩展目录、或走「检查更新」查到，`bt_opt_avail_krels` 会自动把 `6.18.54` 加进列表，`kernel_ok` 转 true，按钮自己就亮——不需要改代码。

## 第 6 步：切换内核那张卡——按系列过滤 + 没包给下载命令

用户在音频页选 6.18 点「复制命令」，拿到的是：

```
MU300_RELEASE=v2026.11.02.1 MU300_KERNEL_BUNDLE=/mnt/mu300-disk/pkg/mu300-kernel-7.3.tar.gz mu300-update kernel 6.18
```

**目标 6.18、包是 7.3 的**。追下去两处毛病：

1. 后端 `kernel_bundles` 只扫 `$PKGDIR` 和 `/tmp`，漏了 `/mnt/mu300-disk/extra/upstream-archive/`；返回项里也没有「这个包到底是哪个内核」的字段。
2. 前端下拉把所有包平铺列出、跟目标内核无关、默认选第一个，切目标时也不重新挑。

### 改法

**后端 `rpcd/airsim-audio` 的 `kernel_bundles`**

- 扫描目录加 `/mnt/mu300-disk/extra/upstream-archive/*kernel*.tar.gz`
- 每个包读包内 `./kernel.release`，新增 `kver` 字段（文件名只标系列，真正小版本在包里）
- `size` 从 `stat -c %s`（busybox 不支持，一直返回 0）改成 `wc -c < file`

实测：

| 包 | kver | size |
|---|---|---|
| `mu300-kernel-7.3.tar.gz` | 7.3.1 | 56121738 |
| `mu300-kernel-6.18.tar.gz` | **6.18.60** | 53175572 |

**前端 `audio.js`**

- 新增 `allBundles` + `refill(k)`：下拉只列**同系列**的包，选项写成 `mu300-kernel-6.18.tar.gz（内核 6.18.60）（50.7 MB）`
- 打开页面时目标内核默认落在 boot 里记的那一档（这台是 6.18），不再一上来指 5.4
- 切目标就重填下拉；某系列一个包都没有 → 下拉锁住

### 用户第二个质疑：干净机器上哪来的包

用户指出：**"别的机器就是单一内核，不联网咋切换，你下载到本地了？"**

核查：`/mnt/mu300-disk/extra/upstream-archive/mu300-kernel-6.18.tar.gz` 是 11-10 19:54 存进去的，53,175,572 字节，跟上游 `github.com/dikeckaan/mu300-linux` 的 release `v2026.11.02.1` 资产 `mu300-kernel-6.18.tar.gz` **字节数完全一致**——是从上游拉下来的存档，不是固件自带。`pkg/` 里那个 7.3 同理。

所以这卡片对干净机器是断的：只认本地包，没包就切不了，也不说去哪儿下。

**补上**：`refill` 判断当前系列有没有包——

- 有 → 显示切换命令，下加载隐藏
- 没有 → 切换命令位置写「（这台机器上没有 X 系列的内核包，先下包）」，下面多出一条 `pre` 放下载命令：

```
curl -L -o /mnt/mu300-disk/pkg/mu300-kernel-6.18.tar.gz https://github.com/dikeckaan/mu300-linux/releases/download/v2026.11.02.1/mu300-kernel-6.18.tar.gz
```

- 「复制命令」按当前该跑的那条走：没包时复制下载命令，有包时复制切换命令

上游仓库从 `/usr/bin/mu300-update` 里读出来的：`REPO=${MU300_REPO:-dikeckaan/mu300-linux}`。

### 顺带确认的两件事

- `mu300-update` 是固件自带（`/usr/bin/mu300-update`），裸跑输出 `kernel 6.18.54 (boot image: v2026.11.02.1; kernel choice 6.18)` —— 印证「槽位 6.18 + 实际 6.18.54」两层是分开记的
- 命令里出现两个 6.18 不是重复：`mu300-update kernel 6.18` 说的是槽位，`mu300-kernel-6.18.tar.gz` 是文件名；真正决定小版本的是包内 `kernel.release`

## 第 7 步：切到 6.18.60、装配件，以及「点安装没反应」的真因

### 内核切换

```
MU300_RELEASE=v2026.11.02.1 MU300_KERNEL_BUNDLE=/mnt/mu300-disk/extra/upstream-archive/mu300-kernel-6.18.tar.gz mu300-update kernel 6.18
```

输出：

```
boot: 2956 modules for 6.18.60 installed into: openwrt
slot b armed: 5 failed boot(s) in a row before Android
boot: updated to v2026.11.02.1 (kernel 24930312 bytes, ramdisk 15369197 bytes)
kernel 6.18 selected. Reboot to start it
```

过程观察：命令不算快，中途 `ps` 能看到 `mu300-update kernel` 两个进程 + 一个 `head -c 45072750`，暂存区 `/mnt/mu300-disk/.mu300-update/boot/` 里 `new` 从 40MB 涨到满，`modules/` 同步增长；这段时间 `device-ramdisk.lz4.new` 一直是 0 字节，别误判成失败。

重启后 `uname -r` = **6.18.60** ✓，音频配件包随即显示「已安装 25/25」。

### 用户报：点「安装蓝牙」，条子从「正在下载……」退回「主包不带蓝牙驱动与 bluez」

```sh
rm -f /tmp/airsim-btopt/state
ubus call airsim-bt bt_opt_install      # 返回 {"ok":true,"state":"download"}
sleep 2; ps | grep -c airsim-btopt-install   # → 0
ls /tmp/airsim-btopt/state                   # → 不存在
```

**根因**：`btopt_install` 里是

```sh
nohup sh "$BT_OPT_RUN" >/dev/null 2>&1 &
```

rpcd 由 procd 托管，这次 ubus 调用一结束，`nohup` 起来的子进程会被一起收走——连第一行 `set_state download` 都没来得及写。

**修法**：

```sh
setsid sh "$BT_OPT_RUN" >/dev/null 2>&1 &
```

设备上有 `/usr/bin/setsid`（另有 `/sbin/start-stop-daemon`）。

复测：调用后 4 秒 `state` 文件已在写 `download`、进程存活；约 1 分钟后 `done`，日志末行 `[btopt] 已装好：hci0 在位（27:93:31:14:22:11）`。

## 第 8 步：音频配件包改成「自己装全」，页面能看出缺什么

### 起因

主服务 `airsim-mu300d` 起不来，逐层剥出来的缺口链：

```
Missing mu300-voice → Missing mu300-audio-dsp → Missing amixer → no audio drivers for 6.18.60
```

手工一层层补齐后服务 running（`audio drivers: 19/19 loaded`、声卡 `sprdphone-sc2730`、DSP 运行、`voice endpoint 01-53`）。诉求是：**这些手工动作必须由程序自己完成**，不能每次都靠人翻目录找文件补。

### 三个关键坑

**① `mu300-audio-dsp` 不能拷贝，只能符号链接**

它内部除了按 `MU300_LIB_MODULES:-/lib/modules/$KREL` 找模块，还会按**自身所在目录**找同级 `modules/<krel>/sprd_audcp_boot.ko`。拷到 `/usr/bin` 就成了孤儿，直接报 `no audio drivers for 6.18.60`；改成 symlink 指向 `EXT/bin/mu300-audio-dsp` 后立刻认出驱动目录，退出码 0。

五个工具（`mu300-audio-dsp`/`mu300-voice`/`mu300-hfp`/`ctlset`/`pcmhost`）全改 symlink 后 `restart` 成功。

**② `amixer` 固件原生不带**

OpenWrt 25.12 用 `apk`，索引从没建过。`apk update`（11213 包）+ `apk add alsa-utils`（1.2.11）解决。

**③ 开机链路本来就是全的**

`/usr/lib/airsim/prepare` 第 19 行 `for c in mu300-at mu300-voice mu300-audio-dsp; do command -v ... || exit 1`、第 23 行 `mu300-audio-dsp install --download`、第 91 行 `mu300-audio-dsp start`；配合 `/etc/init.d/airsim-audio-reserve`（S10 跑 `reserve`）和 `airsim-audio-setup`（S97 跑 `/usr/lib/airsim/audio-setup --resume`）。

断点只在「工具不在 PATH」，所以安装器挂好 symlink 就够，不需要另写开机 load 逻辑。

### 上游为什么没有这些程序

质疑过：「资源不都在 GitHub 上吗，为啥要从 F50 导出」。逐项查实：

- 上游 `dikeckaan/mu300-linux` 仓库有大目录 `kernel/ openwrt/ rootfs/ android/ boot/ gui/ i18n/`
- 其 release `v2026.11.02.1` 给的是 `mu300-extra-panel-offline.tar.gz`（23MB，解开只有 `bin/mu300-panel` + cockpit 网页 + `debs/`，**零 audio**）、`mu300-kernel-6.18.tar.gz`（53MB）、各种 magisk 包
- `dikeckaan/mu300-audio` 仓库直接 **404**

为什么没有：`tools/make-release.sh` 第 318 行有审计闸，发布前发现 `opt/mu300/bin/(mu300-audio-dsp|mu300-voice|pcmhost|ctlset|mu300-hfp)`、`mu300-(audio|voice).service`、`init.d/mu300-(audio|voice)` 等任一就判失败、不许发布。属**主动剔除**（授权/厂商私有实现，`NOTICE` 写「Independent AirSIM integration; not an official MU300 Linux/Audio release」）。**不是内核限制，也不是缺驱动要重编。**

### 补货路径

设备 `EXT/sources.json` 里登记了 `legacy_userspace_archive`：本项目 Release 的 `mu300-audio-5.4.tar.gz`，sha256 `8e2eb2774c485a2df4e28e4e77592a457ffbb626f1dace3b6d1cdc338b786e2b`，用途注明「Only preserved pcmhost/ctlset/mu300-hfp binaries and notices; never its kernel modules」。`bin/` 下五个工具全在。归档已镜像到本项目 `audio-opt-v1.0.4` release。

### 安装器改了什么

`parts/audio/opt/install.sh`：

1. **缺件自动补齐**：外部依赖缺 → `tools_archive()` 走 `api.github.com` 取资产列表 → 定位 `mu300-audio-5.4.tar.gz` → 下载 → `sha256sum` 比对 → 解包 → 逐个 `cp` 到 `EXT/bin` → 仍缺则汇总 die 并写明网络要求
2. **前置判断、不做半套**：补不齐直接停，不留改装到一半的模块目录
3. **`verify()` 补三项**：工具链在不在、`/usr/bin` 链接挂没挂、`amixer` 有没有
4. **dsp patch 幂等**：开工条件从「`.orig` 在不在」改成「查特征串」，从归档补回来的原版也能正确再打一次
5. **备份只留最近两份**：`ls -d "$dest".bak.* | sort -r | tail -n +3 | while read old; do rm -rf "$old"; done`

为什么走 `api.github.com`：设备上 `github.com` 不可达（VPN，curl 000 超时），`api.github.com`（200/0.7s）与 `objects.githubusercontent.com` 可达，附件 API 配 `Accept: application/octet-stream` 能直接下二进制。

### 页面改成按「能不能用」判断

原来 `aud_probe` 的 `installed` 只看 `.ko` 件数和 `dsp_present`，五个工具不全或 `amixer` 缺失时照样报 `installed=true`、`modules_ok=true`，页面显示「已装齐」，人以为好了但服务起不来。

`audio_opt_probe` 现在多报四个字段：

| 字段 | 含义 |
|---|---|
| `tools_ok` / `tools_missing` | `EXT/bin` 下五个工具是否都可执行 |
| `links_ok` | `/usr/bin` 五个链接是否都在且不断 |
| `amixer_ok` | `amixer` 是否在 PATH |
| `ready` | `installed && tools_ok && links_ok && amixer_ok` |

页面（`audio.js` / `maintenance.js`）三态：

| 场景 | 状态 | 按钮 |
|---|---|---|
| 四项全齐 | 已装齐（绿） | 重装 / 重新安装音频模块 |
| 模块在但缺东西 | 缺件（红），点名缺什么 | 补齐缺件 |
| 模块也没有 | 未安装 | 安装 |

`poll()` 失败的 catch 分支不再让按钮永久禁用。

顺带修两处：

- `available` 会把 `6.18.60.bak.2026…` 这类备份目录也列出来 → 过滤 `.bak.`
- `opt_version` 原来先读 `/tmp/airsim-audio-status`（开机脚本的快照，装完新包不刷新），装完仍显示旧版本 → 改成优先读 `EXT/audio-opt-version`（安装器每次装完必写）

### 打包前踩的一个坑

一致性检查 `build/tools/check-consistency.py` 报「rpcd/airsim-bt 里没找到 BT_OPT_FILE」。原因是蓝牙那块早先改成了按内核动态拼文件名（`airsim-f50-bt-opt-$BT_OPT_VER-k$kver.tar.gz`），没有静态常量了，而检查脚本仍按静态常量找。改法：静态 `BT_OPT_FILE` 和 `BT_OPT_VER` 两种写法都认，比对的仍是文件名里的版本号——检查没放水。
