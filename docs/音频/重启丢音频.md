# F50 重启后丢音频：根因、为什么救不回来、怎么根治

2026-11-09 实录。设备 `192.168.77.1`，内核 `6.18.60`，AirSIM `0.1.0.5-r23-6.18`。

## 1. 现象

一次重启后：

```
dmesg:  audio_reserve: 2176 pages not taken: reserved 0 slab 16 anon 9 file 9 free 29 other 2113
/sys/module/audio_reserve/parameters/missing = 2176
/proc/asound/cards → 只有 card0 Loopback（没有 card1 sprdphone-sc2730）
/etc/init.d/airsim status → active with no instances
/usr/lib/airsim/prepare 失败 → agent 与 bridge 都没起 → 127.0.0.1:7581/status 连不上，电话打不了
```

## 2. 根因（源码级）

`audio_reserve.ko`（`kbuild/mu300-audio/kernel/common/audio_reserve/audio_reserve.c`）的机制是：
**开机时把 DSP 要的固定物理窗口（2176 页 ≈ 8.5 MB，`0xaf700000` 起）从页分配器里"抢"出来**。
它靠 `alloc_pages()` 一次块一次块地拿，块里落在目标窗口的页留下，其余暂扣、扫完再还。

关键一行决定了 6.18 上必输：

```c
#if LINUX_VERSION_CODE < KERNEL_VERSION(5, 10, 0) && IS_ENABLED(CONFIG_CONTIG_ALLOC)
static void contig(void) { ... alloc_contig_range() 把可移动的页迁走 ... }
#else
static void contig(void) { }        // ← 6.18 走这里：没有任何迁移能力
#endif
```

而这台机器的内核：

```
CONFIG_COMPACTION is not set
CONFIG_CONTIG_ALLOC 未开
```

**结论：在这颗 6.18 内核上，"已经被别人用掉的页"永远要不回来。** 只要那 8.5 MB 窗口里
有 slab / 匿名页 / 页缓存 / 其它内核页落脚，就永远 `missing > 0`。

`missing > 0` 时 `audio_mem` 不会加载 → 声卡不注册 → `prepare` 失败 → 服务实例不启动。这是**设计好的硬闸**，不是 bug。

## 3. 运行中能不能救？（实测：不能）

模块自带 `retry` 口子（写任意值到 `/sys/module/audio_reserve/parameters/retry` 再抢一次）。
2026-11-09 实拍：

```
清页缓存后 retry #1 → missing 2176 → 1920   （一次就啃下 256 页，都是当时的空闲页）
retry #2..#6（每轮都 drop_caches）→ 一直是 1920
分类：slab 320 anon 186 file 644 free 166 other 604
```

`retry` 只对"当时还空着"的页有效。剩下 1920 页是真被占住的，没有 `alloc_contig_range` 就动不了。
**运行中修不回来，只能重启。**

## 4. 为什么上次重启又能好

窗口能不能干净，取决于开机那 12 秒里页分配器有没有往那 8.5 MB 里撒过东西 —— 是**概率事件**：

- 开机早、加载物少 → 命中概率高（之前的成功来自这种)
- 开机期间多加载了服务（蓝牙 `sprdbt_tty` + WCN 上电、多开的东西）→ 占位概率上升

`btattach` + WCN 上电会申请 DMA/固件缓冲，这是最可疑的"新变量"。

## 4.5 这是 kano 那套 6.18 内核构建的局限，不是 AirSIM 的锅

同一台硬件，换别人家/官方的包就**不需要**这个脚本，原因在对方内核里：

| 情况 | 为什么不会丢音频 |
|---|---|
| 内核开了 `CONFIG_COMPACTION` + `CONFIG_CONTIG_ALLOC` | `audio_reserve` 的迁移路径能编进去，被占用但可搬的页会被搬走腾地方 |
| 内核 ≤ 5.4（本仓库 5.4 线就属于这种） | 模块源码里 `< 5.10` 分支有效，`alloc_contig_range()` 正常工作 |
| 设备树 / cmdline 里把这段物理地址预留了 | 那些页开机就是 `PageReserved`，模块直接算"已占"，`missing` 恒为 0 |
| 厂商 Android 那套 | DSP 内存由 vendor 固件/驱动自己 carveout，压根不走这个运行时抢页模块 |

kano 这条线（`kanoqwq/mu300-linux` 的 6.18 分支）恰好三样全不占：内核 `CONFIG_COMPACTION=n`、
`CONFIG_CONTIG_ALLOC` 未开、DSP 段也没在 DT 里预留 —— **于是只能靠"开机那一把运气"**。
所以：

- 这是**他那套内核配置的局限**，属于上游构建的取舍，不是 AirSIM 插件或我们改名的毛病；
- 我们的 `airsim-audio-retry` 只是给这个局限打补丁：**别人家的包装上也无害**，每轮第一条
  `[ "$m" = 0 ] && return 0` 直接返回，纯空转；
- 真想从根上治，得回到内核配置（重编内核）或 DT/cmdline 预留，那属于 kano 那条线的事，
  我们不改内核、不动启动镜像 —— 他的版本还在更新，我们跟着升级，不给自己挖坑。

## 5. 方案（按风险排序）

### 方案 A：开机多轮重试（安全、可逆）——**已实施（2026-11-09）**

在 `/etc/init.d/airsim-audio-reserve` 的 `boot()` 里，reserve 之后加循环：

```sh
i=0
while [ "$(cat /sys/module/audio_reserve/parameters/missing)" != 0 ] && [ "$i" -lt 20 ]; do
    sync; echo 3 > /proc/sys/vm/drop_caches
    echo 1 > /sys/module/audio_reserve/parameters/retry 2>/dev/null
    i=$((i+1)); sleep 3
done
```

- **好处**：能救回"只是暂时被页缓存占着"的情况；不需要动内核、不动启动镜像、一条命令可逆。
- **上限**：实测被 slab/匿名页占住时救不回来（本次就属于这种）。
- **不做自动重启**：脚本只写日志 + `logger`，绝不由自己发起系统复位 —— 循环比"坏一次开机"更糟。

**落地形态（独立 rc 脚本，不动上游那个 init）**

| 文件 | 装到设备哪里 |
|---|---|
| `build/pkg/airsim-audio-retry.init` | `/etc/init.d/airsim-audio-retry`（`START=11`，紧跟 `S10airsim-audio-reserve`） |
| `ops/install-audio/装音频抢占.sh` | 本机执行：`sh 装音频抢占.sh` |

- 为什么独立：上游音频扩展更新会覆盖 `/etc/init.d/airsim-audio-reserve`，独立脚本不会被顶掉
- 可调：`F50_CLAIM_ROUNDS`（默认 20 轮）、`F50_CLAIM_SLEEP`（默认 3 秒），最坏阻塞开机 60 秒
- 日志：`/tmp/airsim-audio-claim.log` + `logger -t airsim-audio-claim`

**2026-11-09 实测（这台坏 boot 上试跑 4 轮）**

```
round 1 missing=1920
round 2 missing=1904      # 只能再啃下 16 页页缓存
round 3 missing=1904
round 4 missing=1904      # slab 319 anon 198 file 654 free 129 other 604
```

即：**该救的能救回一部分，被 slab / 匿名页占住的这一轮救不回来**，日志会写明 `this boot needs a reboot`。

### 方案 B：把 reserve 提到更早（安全、可逆，收益有限）

现在它在 `S10airsim-audio-reserve`（开机 12.5 s）。可以往前挪到 preinit 末段
（`/lib/preinit/` 里插一个脚本，`80_mount_root` 之后）。越早，别人"撒页"的机会越少。
**但**：preinit 阶段 `/mnt/mu300-disk` 与 uci 未必就绪，要先确认，否则脚本根本跑不起来。

### 方案 C：内核启动参数保留该段（**根治，但要动启动镜像**）

给 `boot.img` 的 cmdline 加一段：

```
memmap=8M$0xaf700000
```

内核启动时就把这 8 MB 标成 `PageReserved`；模块对全 `PageReserved` 的窗口是**直接算作已占**
（源码里 `kernel_reserved` 分支），`missing` 必为 0，**100% 成功**，不再看运气。

代价与风险要说清：
- 这台机的启动不是一个能直接改的 `extlinux.conf`，是 **Android `boot.img`**（TF 卡 `/mnt/mu300-disk/boot/` 里有
  `boot.img`、`prev.body`、`prev.vbmeta`、`boot_b-backup-before-6.18.img`、`device-ramdisk.lz4`）；
- 改 cmdline 要解包 → 改 → 重打包 → 写 boot 分区，**失败会开不了机**；
- 可回滚（TF 卡上有完整备份），但要有人守着设备、能进 9008 / 能换卡。

### 方案 D：改模块放开 `contig()` 的版本条件（不推荐）

把 `#if LINUX_VERSION_CODE < KERNEL_VERSION(5,10,0)` 去掉，理论上能在 6.18 上用 `alloc_contig_range()` 迁移
"可移动但被占用"的页。**但**这台内核 `CONFIG_COMPACTION=n`、`CONFIG_CONTIG_ALLOC` 未开 —— 得先重编**内核**，
不只是重编模块；代价远大于收益，且 slab/其它页照样动不了。

### 不推荐：降频/砍服务换概率

关蓝牙、推迟 wpad 之类只能提高命中率，不能保证；今天已经先把蓝牙开机自启关掉了（见 `docs/蓝牙.md`）。

## 6. 每次重启后的判活三条

```sh
cat /sys/module/audio_reserve/parameters/missing    # 必须 0
cat /proc/asound/cards                              # 必须有 card1 sprdphone-sc2730
/etc/init.d/airsim status                           # 必须有实例（不能 active with no instances）
```

三条都过再谈打电话；`missing ≠ 0` 直接重启，别在运行中折腾（`retry` 只在少数情况下有效）。

## 7. 现状（2026-11-09 收尾）

时间线：这一轮 boot 先失败（`missing=2176 → retry 到 1920 卡死`），按安全策略由用户手动重启一次；
重启后 **`missing=0`**，声卡 `card1 sprdphone-sc2730` 回归，`S11airsim-audio-retry` 因为一进来就
`missing=0` 直接返回（`/tmp/airsim-audio-claim.log` 为空，正是设计行为），服务 `running`。
随后装上 `0.1.0.6-r23-6.18`，`/status` 复核：

```
agent version 0.4.7-mu300.0.1.0.6-r23-6.18
product       AirSIM for F50
devices       Card 1 / Capture hw:1,16 / Playback hw:1,53
audio         audio_available=true
```

结论：**B 路（A 方案脚本 + 少加载 + 手动重启一次）在这台机上够用**；被 slab/匿名页占住的那类 boot
仍然只能重启，脚本会在日志里讲明白，不装死。
