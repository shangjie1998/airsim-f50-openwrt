# 中兴 F50（MU300 / UMS9620）在 OpenWrt 上打通 AirSIM 双向通话

**结论：已实机打通，双向有声，通话正常。** 设备 `192.168.77.1`，内核 `5.4.254-gb50db5b6224c`，OpenWrt 25.12.5，插件 `luci-app-airsim-0.1.0-r22`。

> 为什么不在 Android 上做：F50 的 ROM 没有 `android.app.role.DIALER`，用 `service call telecom 68` 绕过角色后信令全通（拨 10086、挂断都正常），但**下行音频永远是 0**——`pcm_capture=all_zero`、`/dev/snd` 只有 `timer`、`tinymix` 打不开 mixer、`ro.vendor.ag.pcm` 指向的节点不存在。这台机器在 Android 栈下没有可用的语音音频落点，不是配置问题。转 OpenWrt 后由 `mu300-audio` 重建内核模块 + `agdsp.bin` 把 modem 语音 PCM 经 ALSA 暴露出来，AirSIM 只负责转发，这条路才成立。

## 二、装机流程（可重放）

1. 切换到 OpenWrt，确认 `192.168.77.1` 可达。
2. 切 5.4 内核：`mu300-update kernel 5.4`，重启进 OpenWrt，`uname -r` 应为 `5.4.254-gb50db5b6224c`。
3. 校验内核配置哈希（安装器口径）：
   ```sh
   gzip -dc /proc/config.gz | grep -E '^(CONFIG_|# CONFIG_)' | LC_ALL=C sort | sha256sum
   ```
   必须等于 `1057cb97…56b3`，否则音频扩展会拒绝安装。
4. 签名密钥落地：`/etc/apk/keys/airsim-dev.pem`（644，公钥 sha256 `0ce703e7…cf1de`）。
5. 安装 `luci-app-airsim-0.1.0-r22.apk`（离线方式 `apk --no-network add --upgrade`，包 sha256 `849f72fb…cfb8`）。
6. 先做 §三 的两个修复，再 `audio-setup --install` → 重启 → `audio-setup --resume` 自动完成 → `uci set airsim.main.enabled=1` → `/etc/init.d/airsim start`。
7. LuCI → 服务 → AirSIM → 获取六位配对码，iPhone 连 `ZTE-F50` 热点后配对。

开机顺序（已布好）：`S10airsim-audio-reserve`（先占 DSP 内存）→ `S97airsim-audio-setup`（续跑校验，通过后拉 AirSIM）。

## 三、踩到的三个坑（都是上游对"全新设备"假设造成的，与 SIM/APN 无关）

### 坑 1：`/opt/mu300/lib/run-dir.sh` 被新 rootfs 裁掉
`audio-preflight` 第 13 行硬性要求该文件存在，缺失时报 `MU300 runtime library missing`，安装直接失败。
修复：从上游原版补回（4069 字节，644）：
```sh
curl -fsSL "https://raw.githubusercontent.com/dikeckaan/mu300-linux/main/rootfs/overlay/opt/mu300/lib/run-dir.sh" \
  -o /tmp/run-dir.sh
cp /tmp/run-dir.sh /opt/mu300/lib/run-dir.sh && chmod 644 /opt/mu300/lib/run-dir.sh
```
之后 `audio-preflight` 输出 `Matched audio kernel/configuration; call, media and SMS preflight passed.`。

### 坑 2：`stage-device.sh` 在"旧文件一个都没有"时被 busybox tar 打死
`audio-setup --install` 走到暂存阶段报 `tar: empty archive`。原因是脚本里：
```sh
tar -cpf "$SAVE/previous.tar" -C / -T "$SAVE/present"
```
全新设备上 `present` 列表为空，busybox tar 对空列表返回 1 并打印 `empty archive`，脚本 `set -e` 直接中断，`status=failed`，并留下 `$SAVE` 目录导致下次跑又报 `Existing candidate/backup requires review`。

修复方式：**不要改包内脚本**（会破坏 manifest 校验），复制一份打补丁再跑，见 `修复脚本/音频暂存-空列表保护.sh`。核心是两点：
- 没有旧文件时 `: > previous.tar`，不调用 tar；
- `restore()` 里解包前同样加 `-s` 判断。

### 坑 3：`mu300-at` 旧版不认 `-`（从 stdin 读命令）
现象：Agent 来电轮询一直失败，`/api/calls/status` 返回
`"last_poll_error":"MU300 AT request failed (AT+CLCC)"`，但**手动** `mu300-at 'AT+CLCC'` 明明是 `OK`。
原因：插件按新版写法调用
```
/usr/bin/mu300-at -t <sec> -
```
设备自带的旧版（10 月 27 日，10258 字节）不支持 `-`，把连字符当 AT 命令发给了基带，回 `+CME ERROR: 0`，Agent 判定失败。
修复：按上游新版同样四行补上 stdin 支持，见 `修复脚本/mu300-at-补stdin.sh`（原件备份为 `mu300-at.bak-20261107`）。补完 `printf 'AT+CLCC\n' | mu300-at -t 6 -` 返回 `OK`，`last_poll_error` 清空。

## 四、已知限制

- **5G 数据仍然起不来**：5.4 内核下 `/sys` 只暴露 `sipa_dele_reset`，没有 `sipa_dele_wait`，`sipa-dele-start` 拒绝 insmod，`mobile-data` 主动拒绝激活 PDP（防 CFI panic）。modem 侧 `AT+CGATT:1`、`CPIN: READY` 正常。语音走 CS 域不受影响，但**没有上网**；装包需要靠 Mac 侧代理或在 Mac 上下载后 scp 进去。
- **带宽收窄可作备选**：热点是 5GHz/VHT80（`wireless.radio0.channel=36`），音频本身只要 8 kHz 单声道，若出现断续可先收到 HT20 再测。
- **`mu300-at` 补丁会被覆盖**：`mu300-update apply` 若重铺 `/opt`，需要重跑坑 3 的脚本。
- **`run-dir.sh` 同理**：新 rootfs 若再次裁掉，重跑坑 1 的命令。
- **`mu300-voice` 空闲时 dsp 显示 `no reply`** 是正常现象——DSP 只在通话时由 `prepare.local` 拉起，挂断后退出。
- 上游 README 明写已验收机型为 U30 Air、R22 未单独做 F50 实机回归；本文就是 F50 + 7.2.8 硬件在这条路线上的实测记录。
