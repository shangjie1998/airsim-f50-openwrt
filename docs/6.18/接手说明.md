> 结论先放这儿：**中兴 F50 跑 6.18.60 内核，AirSIM 的语音已经真机打通（双向有声）**，

## 2. 为什么必须自己编

上游 `mu300-audio` 是按内核 release 分目录发 `.ko` 的（`modules/<KREL>/`，靠 kit 下载），
但：

- `kits.lock` 只钉 `6.18.58` / `6.18.59`，**没有 `6.18.60`**；
- 所有 kit 下载链接 404（releases、`download/kits-*`、几个 fork 全空）；
- vermagic 必须**字面相等**，差一个小版本就加载不了。

所以只能用 `mu300-linux` 的 6.18.60 源码树自己造 kit、自己编。全过程在
[F50-6.18音频自编.md](F50-6.18音频自编.md)，四个编译坑、三个装机坑都写在里面。

## 4. 装机三步（缺一步就白折腾）

前提：设备当前内核就是 `6.18.60`，且已经有过一次 AirSIM 的音频扩展目录
`/mnt/mu300-disk/extra/airsim-audio/`（跑过 5.4 那套音频安装就会留下）。

```sh
# 1) 传包
scp dist/airsim-f50-0.1.0.4-r22-6.18-audio-modules.tar.gz root@192.168.77.1:/tmp/airsim-audio-6.18.60-modules.tar.gz
scp scripts/6.18/装6.18音频模块.sh root@192.168.77.1:/tmp/

# 2) 装（会在 /mnt/mu300-disk/extra/airsim-audio/modules/6.18.60/ 放模块，
#            把旧 5.4 目录改名备份，并给 mu300-audio-dsp 打两处放宽补丁）
ssh root@192.168.77.1 'sh /tmp/装6.18音频模块.sh --install'

# 3) 必须重启（audio_reserve 要在开机 S10 抢那 9MB，中途 insmod 抢不到，且模块是 permanent 卸不掉）
```

重启后用 `sh /tmp/装6.18音频模块.sh --verify` 或看这几条：

| 判据 | 期望 |
|---|---|
| `mu300-audio-dsp drivers` | 打印 `/mnt/mu300-disk/extra/airsim-audio/modules/6.18.60` |
| `mu300-audio-dsp status` | `drivers: 19/19 loaded`、`memory: 0 pages missing`、`power-up: yes` |
| `cat /proc/asound/cards` | 出现 `1 [sprdphonesc2730]: sprdphone-sc2730` |
| `dmesg \| grep aud_send_cmd` | `out,cmd ... ret-value:0`，且没有 `failed to get command` |
| `wget -qO- http://127.0.0.1:7581/status` | `audio_available: true`，`devices = {Card:1, Capture:"hw:1,16", Playback:"hw:1,53"}` |

## 5. 两处必须放宽的地方（脚本自动打，原文件备份成 `.orig`）

1. **`set_fits()`**：原本拿模块包里 `KERNEL` 声明的 `CONFIG` 与设备 `/proc/config.gz` 的
   sha256 逐位比，不等就报 “built for another build of it”。
   这台设备是 `233c7a62…`，自编树是 `d5628675…`，只差
   `CONFIG_DEBUG_INFO_COMPRESSED_ZSTD`、`CONFIG_DEBUG_INFO_BTF_MODULES` 两个**纯调试项**
   （交叉链 gcc 11 vs 上游 gcc 13+ 容器）。所以放宽为「声明了 CONFIG 就放行」。
2. **`dsp_alive()`**：原本用 `aplay` 往 `hw:<card>,0` 写 192000 字节当探针，
   真机上必报 `pcm_write: write error: I/O error`（**没通话场景 DSP 不消费 voice PCM**），
   属于假阴性。放开了那句 `|| return 1`，判活改看 dmesg 的 `aud_send_cmd out,cmd ret-value:0`。

**补丁别叠两层**：两处要写在同一个 awk 程序里、始终从 `.orig` 生成。先打 A 再以 `.orig`
为基准打 B，会把 A 冲掉（我踩过，装完满屏 “built for another build of it”）。

## 6. 已知未修复 / 未验证的问题

1. **`arecord -D hw:1,16` 在没有通话时报 `Invalid argument`** —— 正常，没有上行流就没得读；
   但不通话时也没法用它做自检，判活只能靠 dmesg。
2. **`mu300-audio-dsp status` 的 `power-up` 一栏有时显示 `unknown`** —— 它会问 “有没有 alsa-utils”，
   设备上 `amixer` 在 `/usr/lib/airsim/bin` 里、不在默认 `PATH`，所以脚本里必须显式带上
   `PATH=/usr/lib/airsim/bin:/opt/mu300/bin:/opt/mu300/busybox-bin:...`。`/etc/init.d/airsim` 已经带了。
3. **设备上没有 `/usr/bin/timeout`、`/bin/timeout`**，只有 `/opt/mu300/busybox-bin/timeout`，
   `prepare.local` 的 PATH 里带着它，别乱改 PATH。
4. **上游 `audio-preflight` / `audio-setup` / `stage-device.sh` 仍写死 5.4**
   （`KREL=5.4.254-gb50db5b6224c`、CONFIG `1057cb97…`），所以 6.18 走不了官方
   `audio-setup --install`，只能按第 4 节那三步手装。要不要把 6.18 的 CONFIG 哈希与
   `modules/<krel>+<config12>` 口径并进上游脚本，**还没定**。
5. **没出过签名 apk**（要能跑 apk-tools 3.x 的 Linux；Mac 上没 Docker）。
   自编包公钥跟 release 那把不同，设备要先 `apk del luci-app-airsim`，会连 `/usr/lib/airsim`
   和音频组件一起清掉，得重装。
6. **6.18 还没有“完整覆盖安装包”**，现在只有音频模块。要不要也出一个，待定。

## 7. r23 已升级（2026-11-09）

上游 `v0.1.0-r23`（Tailscale 私网配对 + 云端接收缓冲，Pre-release）已并入，版本 `0.1.0.5-r23-6.18`，
已真机通话验证（下行 476 / 上行 459 / 收到上行 475 / 丢上行 8 / 静音 18 / `last_error` 空，双向听清）。

升级方式：`src/` 整棵换成上游 r23 原样，个性化改动全部在 `overlay/f50/` 里重新叠，
不再手改 `src/`（`src/` 一旦被改，下次升级就没法做 diff 了）。

构建：`sh overlay/f50/build.sh`（本机 Go 1.24.7 交叉编，`GO_SDK` 可覆盖），
**不再需要云主机**；上游的 `src/plugin/scripts/build.sh` 依赖 git 基线提交，本仓库没有 `.git` 历史，跑不通，别用。

注意：r23 的 Tailscale 配对与云端缓冲协商**未启用、未验收**，包内只走上游原有路径。

- **Tailscale 私网配对**：设备上没有 `tailscale0`（没装 tailscale、`tunnel_ip` 为空），要测必须先装 tailscale 并登录账号。
- **云端接收缓冲**：档位来自客户端 `answer` 报文的 `audio_buffer_version/mode/ms`，设备侧没有现成观测点（`/status` 不暴露 `uplink_buffer_target_ms` 等字段）。
  真要验，得先加一条只打印协商结果的调试日志，再对比默认 / 手动 720ms 两通的丢帧与听感。
- 2026-11-09 决定：这两项先不测，按“已编译未验收”记录。
