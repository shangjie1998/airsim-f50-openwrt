# F50：备份/恢复 + 维护页 —— 落地方案（待确认）

来源：M8 的 `rpcd/airsim`（`backup_make`/`backup_restore`/`airsim_fingerprint`）+ `maintenance.js`。
**不是照抄**，按 F50 的路径、指纹源、服务名重写。

## 一、备份什么、不备份什么

| 进备份 | 说明 |
|---|---|
| `/etc/config/airsim` | 服务开关、LAN 接口 |
| `/etc/config/f50-bt` | 蓝牙开关状态（关了重启仍为关） |
| `/mnt/mu300-disk/extra/airsim/data/` | `agent-id`、配对/seen 表（真分区，不在 tmpfs） |
| `meta.json` | 格式标识、指纹、短 ID、型号、主机名、插件版本、创建时间 |

| 不进备份 | 原因 |
|---|---|
| 日志、`/tmp` 下任何东西 | 重启即丢，且可能含隐私 |
| 短信正文、号码、录音 | 隐私 |
| `audio/*.ko`、`/usr/lib/airsim/deps/*` | 6MB 级二进制，重装包即可恢复 |
| `backup-0.1.0.*` 目录 | 是本插件自己的历史备份，备份里再装备份没意义 |

预计体积：**顶多几十 KB**，远低于 8MB 上限（上限保留，防止别人塞大包）。

## 二、指纹（防"别人的备份装到我机上"）

沿用 M8 的算法，源换成 F50 实测可用的两个：

```
sha256( /sys/block/mmcblk0/device/cid  + "|" + /proc/device-tree/serial-number )
```

F50 实测值：`cid=ea010e325931384347102037d0fe5c00`、`sn=009238d10a2acb06`。

- `mmcblk0` 是 eMMC，**不随 TF 卡更换而变**；状态数据在 TF（`mmcblk1p1`），换卡后反而能靠备份把 `data/` 还原回去 —— 这点比 M8 的场景更实用。
- 指纹不符直接拒绝，并回显两边短 ID（前 8 位），方便判断"是不是拿错文件了"。
- 型号只做展示：`Spreadtrum UMS9620 SoC`；主机名 `mu300`。**不用型号做校验**（两台 SoC 名一样，校验不住）。

## 三、接口怎么加：新增独立 rpcd，不改上游脚本（推荐）

F50 现在的 `usr/libexec/rpcd/airsim` 是**上游文件**（整份在 `files/` 里覆盖）。直接往里加 `backup_make`，等于把上游文件长期占住，以后上游每次改这个脚本都要重搬——这正是 M8 账本里最贵的第③类改动。

所以改走"新增独立文件"：

| 新增文件（全部在 `overlay/f50/files/` 下） | 作用 |
|---|---|
| `usr/libexec/rpcd/airsim-backup` | 新 ubus 对象 `airsim-backup`，两个方法：`make`、`restore`，外加 `fingerprint` |
| `usr/share/rpcd/acl.d/luci-app-airsim-backup.json` | 只授这两个方法给 LuCI 会话 |
| `usr/share/luci/menu.d/luci-app-airsim-maintenance.json` | 新菜单项「维护」，order 40 |
| `www/luci-static/resources/view/airsim/maintenance.js` | 维护页本体 |
| `www/luci-static/resources/view/airsim/ui.css` | 维护页样式（M8 的设计系统原样搬，S 档；旧三页暂不动，留到第 3 项） |

好处：**上游 `rpcd/airsim`、`menu.d/luci-app-airsim.json`、`manage.js` 一行不动**，升级零冲突。

## 四、维护页放什么

1. **备份**：卡片显示指纹短 ID、型号、主机名、版本 → 按钮「生成备份」→ 前端收到 base64 转 blob 下载，文件名 `airsim-f50-backup-YYYYMMDD-HHMM.tar.gz`。
2. **恢复**：拖拽区 + 选文件 → 解析 `meta.json` 显示"这份备份来自 XX、创建于 XX"→ 二次确认弹层 → 提交 → 回显"已恢复，服务重启中，之前现场留在 `/tmp/airsim-before-restore-*`"。
3. **版本说明**：当前插件版本、内核线、支持的机型（只读）。
4. **插件更新**：复用上游已有的 `airsim` 对象的 `updates_status` / `update_install`（不新增接口）。

页面上**不做**：删除备份、清空配对、重启设备。

## 五、恢复流程（含安全阀）

1. base64 → 字节数 > 8MB 直接拒；
2. `tar tzf` 列表必须全部落在白名单：`./meta.json`、`./config/(airsim|f50-bt)`、`./data/*`，多一条就拒（防借备份覆盖 `/etc/passwd`）；
3. `meta.json.format` 必须等于 `airsim-f50-backup`，`format_version > 1` 拒（防新格式塞进旧插件）；
4. 指纹比对，不符拒；
5. 覆盖前把现场拷到 `/tmp/airsim-before-restore-<时间戳>`；
6. 停 `airsim` → 写配置与 data → `enable` + 后台 `start`（**只重启服务，不重启设备**）；
7. 回显 `before_copy` 路径 + `restarted`。

## 六、验收判据（装机后逐条跑）

| # | 动作 | 通过标准 |
|---|---|---|
| 1 | 点「生成备份」 | 下载到 `airsim-f50-backup-*.tar.gz`；`tar tzf` 只含 meta + config + data |
| 2 | 改坏一个 uci 值（如 `interface`）→ 拖回备份 | 服务自动重启，`/status` 恢复，`paired_clients` 回来 |
| 3 | 手改 `meta.json` 的 fingerprint 再导 | 拒绝，提示"不是本机的"，回显两个短 ID |
| 4 | 往 tar 里塞 `./etc/passwd` 再导 | 白名单拒绝 |
| 5 | 重启设备 | `data/` 仍在（在 TF 真分区），配对不用重来 |

## 七、风险与回退

- **风险 1**：新增 ubus 对象需要 acl 授权，漏了就 403 —— 装机后先 `ubus list | grep airsim-backup` + 页面点一次。
- **风险 2**：页面下载 base64 在旧 LuCI（`preferences` 版本）上走 blob 可能有兼容问题 —— 备选是后端落地到 `/tmp` 再给下载链接；先试 blob。
- **风险 3**：恢复时写 `/mnt/mu300-disk` 若 TF 只读/掉盘 → 回显明确错误，不半途覆盖。
- **回退**：整项只新增文件、不改上游；出问题删掉这 4 个文件 + 重启 rpcd 即可，二进制一个不动。

## 八、工作量

- 后端 `airsim-backup` 脚本 ≈ 130 行（照 M8 改写路径与服务名）
- 页面 `maintenance.js` ≈ 180 行（备份/恢复两卡片 + 二次确认）
- `ui.css` 直接搬 M8 原文件（279 行），不做改动
- 不动 Go，不重编二进制，不打包新版本（先出 `0.1.0.7` 时再一起进包）
