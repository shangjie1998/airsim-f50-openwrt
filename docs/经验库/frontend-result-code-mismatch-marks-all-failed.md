## 适用场景
前后端分离的页面里，记录/日志列表要根据后端返回的结果码渲染成功、失败标签或颜色；功能其实正常，但状态显示普遍不对、或某类结果被误标。

## 关键做法
先到后端源码或接口实际返回里确认结果码的真实取值集合（注意成功往往不只有一个码，测试类另有码），建立明确映射，再让前端按集合判定成功；映射不到的未知码按原值显示，不要一律当失败。记录行信息多时改成两行：首行放时间、事件、状态胶囊，次行放明细（含 HTTP 码等）。改完拿一条已有的真实记录回读渲染文本与截图确认，而不是只看代码改得对不对。

## 踩过的坑
按语义猜字段值（`success`）去比后端枚举（`sent`），会让所有记录静默标红，且不报任何错误——页面看着"能显示"，最容易漏掉。单行多列网格在窄卡片里会把明细（HTTP 码）挤到看不见，改两行后能自然折行。
