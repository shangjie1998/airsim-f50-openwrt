## 适用场景
设备侧同时存在"权威主路径"和"兜底路径"两条取数链路（如需要身份证明的网关接口 vs 免认证的本地事件流）。当主链路（注册、心跳、推送、鉴权）修通后，客户端原本正常的功能反而消失、退回默认值或只剩部分数据。

## 关键做法
1. 先回读数据源本身，确认字段齐全且在实时更新——不要一上来就怀疑数据源。
2. 读客户端源码里的取数优先级，找出它第一优先、且需要前置条件（如验证通过才返回）的那条接口。
3. 把这条主接口的字段集合与兜底接口逐项对比，缺哪个就补哪个，并在中间转发层原样透传，不要只在本体补。
4. 验证以客户端实际显示为准，不看接口自检是否通过。

## 踩过的坑
兜底路径会长期掩盖主路径缺字段的缺陷：主路径不通时客户端退回兜底，功能看着正常；主路径一修好，客户端改走权威接口，缺字段立刻暴露。这种"改好一处、坏另一处"最容易误判成新改动引入的回归，实际是旧缺陷被暴露。

只在数据源补字段、不在中间转发层透传，客户端照样看不到；只验证接口返回有字段、不验证客户端显示，也会误判为已修好。
