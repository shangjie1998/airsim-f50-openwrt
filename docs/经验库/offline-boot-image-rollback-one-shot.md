## 适用场景
嵌入式设备上装了多个内核（厂商旧版 + 自编新版），新内核缺某个驱动导致服务起不来，需要切回旧内核，而设备此时没有网络或没有余额。

## 关键做法
先读备份镜像的元数据再动手：备份目录里的 `.kernel` / `.tag` 文件说明备份镜像带的是哪个内核、哪个版本；确认这些值就是目标内核后，再执行设备自带的回退子命令（本例 `mu300-update rollback-boot`）。回退命令会把备份镜像体写回启动分区并校验哈希，同时把内核选择设成备份记录的值，重启后即生效。验证看三项：`uname -r` 是否为目标版本、服务状态是否为 running（而非 active but no instances）、音频类能力标志是否为 true。

## 踩过的坑
回退是一次性的：它只把 `prev.body` 写回启动分区，不会把当前镜像另存为新的 prev。所以离线环境里这招只有一次机会；想再回到新内核必须走联网下载那条路（`mu300-update kernel <版本>`）。动手前务必确认备份内容确实是旧内核，否则会把唯一一次回退机会浪费在错误镜像上。另外设备重启属高危操作，不能由自动化脚本代发。
