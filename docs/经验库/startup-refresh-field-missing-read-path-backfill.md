## 适用场景
自建常驻服务把某个字段只在启动阶段的后台"静态刷新"里赋值，而读接口照样返回该字段缺失（字段带 omitempty 时尤其像"代码写了却没生效"）。

## 关键做法
先判定落不落地：直接请求接口看原始 JSON，不要用系统日志判断。
不要顺着启动时序去查为什么没跑到；在返回该字段的 handler 里加兜底：取快照发现为空时，用 `sync.Once` 起一个后台 goroutine 重新采集一次并写回，避免阻塞请求本身。
改完重启服务，连续两次请求接口，两次都带该字段才算完成。

## 踩过的坑
- 日志法不可靠：嵌入式设备的内核/音频日志会把应用自己的 log 刷没，容易误判成"分支没执行"。
- 覆盖安装后除核 md5，还要看进程实际在跑的路径（可能是软链），否则不确定改的是不是正在跑的那份。
- 兜底采集要放在后台 goroutine，直接在 handler 里做采集会让接口变慢甚至超时。
