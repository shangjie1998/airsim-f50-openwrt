## 适用场景
OpenWrt 插件的打包脚本带「先编再打」开关（例如 `--build`），运行后长时间没有输出，go build 进程占着不动，前台等待和后台任务都拿不到结果。

## 关键做法
先结束卡住的打包脚本与 go build 进程；只运行项目自己的编译脚本，确认输出二进制的时间戳已更新；再运行不带「先编」开关的打包步骤，只做归档与校验；最后核对 dist 下产物的大小与 sha256，确认是新包。

## 踩过的坑
把编译和打包串在一条链里时，go build 一卡住整条链就静默挂起，日志为 0 字节，看不出停在哪一步。拆成两步后能立刻看到「编好」「打好」两段输出，也能用二进制时间戳判断是否真的重编。若同名旧任务还在跑，先清掉，避免两个 build 抢同一输出目录。
