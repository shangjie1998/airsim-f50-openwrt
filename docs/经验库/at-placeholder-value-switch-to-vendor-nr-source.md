## 适用场景
嵌入式/OpenWrt 蜂窝设备 SIM 已注册、号码正常，但页面或推送里的信号强度始终为空或「暂未提供」，运营商名字也空着；设备是 5G 独立组网（SA）或 NR 优先接入。

## 关键做法
1. 先确认后端用的是哪条测量命令，以及该命令是否覆盖当前制式：`AT+CSQ`（含 `AT+CESQ` 前两格）只覆盖 2G/3G，NR 接入时固定回 `99,99`；`99` 是「无可用测量」的占位值，不是 0，也不能当偶发超时。
2. 命令**有成功返回但值是占位值**时，不要重试同一条命令，改找厂商自带的电平接口。常见形态是 ubus/CLI 暴露的服务小区结构（本机为 `ubus call mu300.modem signal {"slot":"0"}` → `sig/lte.rsrp`，单位 dBm），原厂首页信号格取的通常就是这份。
3. 运营商同理：核对刷新路径是否真的发了 `AT+COPS?`，只发 `CPIN`/`CEREG`/`CSQ` 的路径不会有运营商；把 PLMN（如 `46001`）翻成中文名。
4. 页面拿到卡号还要数值对齐：`card` 与 `current` 必须是同类型数字（`json_add_int`），一字符串一数字会被判成「未驻留」而不显示实时电平。
5. 确认方式：真机取 `signal_dbm` 与 `operator` 是否为合理值（RSRP 常见 -80 上下），不是看命令有没有报错。

## 踩过的坑
- 把 `+CSQ: 99,99` 当「晚点再试」：它永远不会变成有效值，重试无意义。
- 在持有 modem/状态写锁时执行外部命令（uber/exec 5 秒），会卡住整个状态读取；兜底取值要放在锁外。
- 只补信号不补运营商，页面一半有值一半空，容易误判修没修好。
- RSRP 与手机五格图标不等价，数值偏保守属正常，别调阈值凑漂亮数字。
