## 适用场景
需要在网页上走完"生成一次性凭据"的表单（pat、app key、恢复码一类），并在同一次自动化里把值取回交给后续步骤。适用于脚本驱动浏览器、靠页面点击完成创建的流程。

## 关键做法
按操作顺序建表单：名称 → 有效期 → 仓库范围 → 权限级别，先确认权限下拉已收起并能看到 Access: Read and write 字样，否则后续点击会被下拉浮层遮挡。

点最终生成按钮前预留读取时机，不要只依赖点击后的页面跳转。很多这类页面会先弹一次确认框，第二次确认按钮才是真正的提交；点下后立刻在同一 cell 内读值，不要等到下一轮工具调用。

值通常落在一个 disabled 的只读 input 里，页面文本抽取抓不到。用结构化读取遍历 input 元素的 value 属性来取，命中后立即结束，不做多余导航。

一次没取到不要在原页面反复尝试——这类值一旦离开当前页面就不会再显示，只能删除后重建；删除走确认对话框，然后从新建表单重新走一遍。

## 踩过的坑
第一次按常规方式"点生成 → 等加载 → 读页面文本"，页面已跳回列表，token 值彻底丢失，只能删除重建。根本原因是页面文本渲染不含 input 的 value，而跳转又发生在读取之前。

表单里权限下拉展开时会盖住下方的 Access 按钮，直接点击报目标被遮挡；先按 Escape 收起菜单、再滚动到目标位置点击才能成功。

提交按钮存在两个同名元素（页面上的和确认弹窗里的），按文本查找会命中前者使点击无效，需要读一次快照区分二者。
