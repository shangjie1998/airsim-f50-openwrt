## 适用场景
设备上的 agent、daemon 在运行期功能正常，但重启后配对信息、token、密钥这类状态全部丢失，表现为"用着没事、一重启就掉线/要重新配对"。

## 关键做法
1. 先用 `readlink -f <状态默认目录>` 和 `ls -ld /var` 确认真实落点。这类固件常把 `/var` 软链到 `/tmp`（tmpfs），默认的 `/var/lib/xxx` 看着存在，实际在内存盘。
2. 再用 `/proc/<pid>/environ` 确认服务进程是否真的被设了覆盖数据目录的环境变量；目录"存在"不等于有覆盖。
3. 改在服务脚本的环境变量上钉死，不靠程序默认值：`AGENT_ENV="...  AIRSIM_DATA_DIR=/opt/<prog>/agent-data"`，目标选 `df -h` 里挂在真实块设备（`/dev/mmcblk*` 或 overlay）且剩余空间够的路径。
4. 安装脚本加一次性迁移：目标已存在就不覆盖（避免冲掉用户新配对），只搬关键状态文件，`chmod 700` 保持权限一致。
5. 验证：重启若被安全策略阻断，可做等价验证——先备份再删掉易失目录、重启服务，然后同时检查"易失目录不再被重建""持久目录内容不变""接口里配置类字段仍为真且标识一致""对外连接重新建立"。

## 踩过的坑
- 只看目录存在会误判：`/var/lib/xxx` 确实在，但它就是 tmpfs 上的路径。
- 迁移必须带"目标不存在才复制"的判断，否则升级会覆盖用户刚配对的数据。
- 重启后第一发外网请求常有一次超时失败（如 http2 等响应头超时），紧接着恢复，属建连失败，不要误判成持久化没生效。
