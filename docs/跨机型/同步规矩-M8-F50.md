# F50 ↔ M8：一端开发、两端兼容的同步规矩

两台机是两条独立线：**F50 走 OpenWrt 6.18 单卡，M8 走 OpenWrt 6.18.54 双卡 16k**。
同一个功能在一端做出来，搬到另一端**从来不是复制粘贴**——硬件参数、卡槽模型、采样率、包结构全都不同。
所以这里定死一条流程：**AI 先判可行 → 人点头 → 才落地 → 各自真机验**，任何一步跳过都算违规。

## 一、三档分类（先看这个文件属于哪一档）

| 档 | 含义 | 处理方式 |
|---|---|---|
| **S（shared）** | 纯视觉/文案资产：`ui.css`、`ui.js`、`*.html`、文档、README | 可参考搬运，但**仍要人确认**，落地后两端各自截图核对 |
| **R（rewrite）** | 逻辑与参数同构但取值不同：`internal/audio/*`、`internal/gateway/*`、`cmd/*`、页面 `*.js`（绑数据）、`acl/menu json` | 必须按目标机常量改写：ALSA 节点、采样率、卡槽、机型串；改完两端分别验 |
| **D（device）** | 设备专属：`pkg/`、`m8-pkg/`、`install.sh`/`uninstall.sh`、`*.init`、`modules/`、`kbuild/` | **禁止跨端搬**。照抄等于把另一台的装机路径带进来，必炸 |

分档不是拍的，跑脚本看：

```sh
python3 build/tools/sync-m8.py                # 全量报告
python3 build/tools/sync-m8.py --only shared  # 只看能搬的
```

## 三、同步流程（每次照走，不许跳）

1. **跑基线**：`python3 build/tools/sync-m8.py`，拿到本次要动的那几行的分档。
2. **AI 判可行**，产出一段结论（贴给人看），四句话必须齐：
   - 这次搬什么（文件 + 属于 S/R/D 哪档）
   - 哪些取值必须改（列出目标机的 ALSA 节点 / 采样率 / 卡槽 / 机型串）
   - 有什么拿不准的（要么列验证动作，要么说"没验过，不敢保证"）
   - 建议：直接搬 / 改写后搬 / 不搬
3. **人确认**。没点头不许动文件——这一步是硬闸，不是形式。
4. **落地**：只改本端 overlay，不碰 `src/`；改上游文件必须首行打 `// M8:` 或 `# F50:` 留痕。
5. **本端自验**：编 → 装 → 真机跑 → 留证据（命令输出/截图）。
6. **另一端再验**（若这次是双向同步）：验证通过才写进各自的账本/坑表。

## 四、UI 样式同步口径（重点）

- **视觉真源是 M8 的 `ui.css`**（279 行，`:root` 里一套 `--as-*` token：底色 `#f5f5f7`、玻璃卡、圆角 20/12、毛玻璃 22px/180%）。
- F50 **只搬 token 与组件样式**，不搬页面里的数据绑定（那边绑的是双卡/电量/分池字段）。
- F50 目前是"整文件替换上游页面"，所以落地方式建议：新增 `overlay/f50/files/.../airsim/ui.css`（同样的 token 名），页面 js 里只做**最少的** class 引用改动；**禁止**把 M8 的页面整份塞进 F50 覆盖上游。
- 冒烟判据（两端通用）：主页、通话页、短信页、设置页各截一张，比对底色、卡片圆角/阴影、按钮蓝 `#0071e3`、深色底 `#101013` 是否一致；布局信息密度可以不同（设备功能本就不同）。

## 五、云端心跳 / 拨号超时类：**不许跨端照搬**

M8 上出现"云端心跳断、媒体拨号 TLS 超时"，**不能推导 F50 也有**。原因：

- 两条链路的路由不同（F50 走 `sipа_eth0`/蜂窝 + flow_offloading=1；M8 是另一套网卡与探针内核）；
- 双卡与单卡的 AT 上下文、选卡残留完全不同，很多"心跳丢"其实是拨号选了别的卡（见 M8 的 `docs/PENDING-cloud-dial-missing-sim-account.md`）；
- TLS 预算（TCP 8s→15s、握手 8s→30s）是**按蜂窝实测调的**，照抄到另一台可能把真问题掩盖成超时。

**正确做法**：在目标设备上先复现（留 `/status` + 日志 + 时间戳），确认症状同源，再谈改。
复现不了就记"未复现"，别改。

## 六、禁止清单

- 禁止把 `m8-pkg/` 的任何文件搬进 F50；反之亦然。
- 禁止把 M8 的 `hw:0,9` / `hw:0,18` / 16 kHz 带进 F50（F50 是 `hw:1,16` / `hw:1,53` / 8 kHz）。
- 禁止把 F50 的 `airsim-audio-retry` 塞进 M8（M8 没有 DSP 抢页问题，装了纯空转）。
- 禁止用"另一端已经验过"当作本端验收证据。
- 禁止在两端仓库之间共享路径、脚本参数化、或做软链（工具放 `~/Documents/doubaokaifagongju`，项目脚本各留各的）。

1. **#1 + #7（备份/恢复 + 维护页）**：收益最大、不碰音频、不动内核，一台做完另一台抄结构只换路径。

### 9.4 为什么维护页没有“下载并更新”

F50 插件的更新检查读的是**上游作者的仓库**（`kai-wu-cortex/airsim-mu300`），点“下载并更新”会把上游整包装上来，直接盖掉本项目的 `overlay/f50`。所以本页只保留「检查更新 + 打开项目 Release」，安装一律走手动下包。

### 9.5 本轮踩到的坑（都已在代码里注释）

1. **`jshn` 的布尔只认 `1/0`**：`json_add_boolean service_running "true"` 渲染出来是 `false`。必须 `_run=1`。
2. **`"$(pgrep -f 'pattern' …)"` 里的单引号是字面量**：双引号内的单引号不会被 shell 去掉，`pgrep` 拿到带引号的模式永远匹配不上。改成先 `if pgrep …; then _run=1; fi`。
3. **`/etc/init.d/rpcd restart` 会踢掉 LuCI 会话**：页面卡“加载视图中…”，且旧标签页的 JS 会一直坏（`"%s/%s.js%s".format is not a function`）。**处理办法：`/etc/init.d/uhttpd restart` + 开新标签页重登**，不用怀疑页面代码。
4. **`apply.py` 的权限**：带 `shebang` 一律 755，其余 644——新增的 `etc/init.d/airsim-call-forward`、`usr/lib/airsim/call-forward` 靠这条才可执行。

- **需要重编 Go 的**：`+86` 号码补全（`module-agent/sms.go`）、`pair_clients`/`pair_remove` 的原生接口（`main.go`/`gateway.go`）。按约定，等这几项 UI/脚本都落地了再一次性编译。

### 10.1 短信发送：参数与回执双坑（第三枚补丁）

`overlay/f50/patches/AirSIM-mu300-sms-send.patch`（只动 `AirSIM/module/module-agent/mu300_sms.go`）：

1. **参数**：上游调 `/opt/mu300/bin/mu300-sms send --stdin`（号码\n正文走标准输入）。F50 厂商脚本**整份没有 `--stdin`**，只认 `send NUM TEXT`，喂 `--stdin` 被当号码 → `die "send needs a phone number and a text"`。补丁加 `mu300SMSSendAcceptsStdin()`：读脚本内容判断有无 `--stdin`，有则走上游老路，无则用位置参数 + `strings.Cut` 拆号码/正文。
2. **回执**：厂商成功打两行——

```
submitting to 10000 (18 octets, 4 UCS-2 units)
sent (2)
```

   上游正则 `^sent \(reference [0-9]+\)$` 两个条件都不满足（行首锚 + `reference ` 字样）。补丁改为 `(?m)^sent \((?:reference )?[0-9]+\)$`。
3. **不做“失败换姿势重试”**：提交失败时重试可能让短信已发出去却再扣一次，宁可报未确认。

**判定方法（跨端通用）**：`grep -c -- '--stdin' /opt/mu300/bin/mu300-sms`，0 就是位置参数版。

### 10.2 短信读取：上游写死路径 vs 厂商真实池

上游 `mu300_sms.go` 把池写死成 `/etc/mu300/sms-pool/msg`，F50 厂商实际在 `/etc/mu300/sms`（`/opt/mu300/lib/sms-pool.sh` 归一化）。原症状：`/api/sms` 恒 503 `native SMS inbox unavailable`。
F50 做法：不碰 Go，新增 `overlay/f50/files/etc/init.d/airsim-sms-pool-link`（`START=97`，幂等建软链 `/etc/mu300/sms-pool -> sms`），`install.sh` 里 enable+start。agent 每 3 秒扫池，链路一起来就恢复。
**M8 若上游已改对路径则无需此步；先 `ls` 确认哪条存在再决定。**

### 10.3 “来源未知” → 每条补 `sim`

`rpcd/airsim-sms` 的 `forward_sms_list()` 原样重建列表时丢了槽位，页面 `sms.js` 判 `m.sim || card?'SIM1':'来源未知'` 就落到兜底。
改法：`_simname="SIM$(( ${_used:-0} + 1 ))"`，每条 `json_add_string sim "$_simname"`。单卡设备恒 `SIM1`，双卡设备按 `sim_used` 自动分开，**不需要为双卡再写一套逻辑**。

### 10.4 已配对客户端：列表 + 删除

- **列表**：上游 Go 没有 `/pair/clients`（`404 page not found`），rpcd 层又看不到“哪把密钥在鉴权”，所以只能改 Go——`overlay/f50/patches/AirSIM-pair-clients.patch`：`gateway.go` 加 `lastUsed map[string]int64`（`authenticate()` 里 HMAC 比对成功处记时间）、`ClientInfo`/`fingerprintOf`/`Clients()`，在线窗口 120 秒；`main.go` 加 `/pair/clients` 路由。`rpcd/airsim-pair` 的 `list_clients()` 优先 `curl $AGENT/pair/clients`，命中 `"clients"` 直接用，否则退回读 `vowlan-clients.json`（老二进制不炸）。
- **删除**：`vowlan-clients.json` 是 Go 写的**一整行 JSON 数组**，`pair_remove` 原实现按“一行一把密钥”切 → 序号 2 永远删不掉、序号 1 会把整行抹掉。改成 `jsonfilter -e '@[*]'` 先拆成一行一把、按序号过滤、再拼回一整行数组原子替换，之后重启 `airsim` 让网关重载密钥。
  **通用教训**：这个文件形态决定“按行处理”一定错，任何端要改它都得先按数组元素拆。

### 10.5 补丁治理层（F50 已上，M8 建议照抄）

- `overlay/f50/patches/manifest.tsv`：四列 = 补丁文件 / 上游仓库（空=无对照）/ 已合并标志串 / 锚点串（`;` 分隔）。
- `build/tools/check-patches.py`：① 干净 `src/` 副本上 `patch --dry-run` 判干净/打不上；② 拉上游最新文件比对（**上游没有 `plugin/` 这层前缀，脚本自动去前缀**），命中已合并标志串 → “已合并，删补丁”；锚点缺失 → “锚点缺失”。
- 已挂进 `overlay/f50/build.sh`（rsync 之后立刻跑，只打表不阻断；**真正打补丁的 `apply.py` 打不上就退出，让构建失败**）。
- 规则见 `overlay/f50/patches/README.md`：不许 `--fuzz`/`-l`/`--forward` 绕过；冲突由人改补丁；**上游自己合并了同功能，我们也合并（删我们的补丁跟随上游）**；补丁只做加法。

### 10.6 本轮踩到的坑（新增）

1. **跨网短号发不出去 ≠ 代码 bug**：联通卡（`AT+COPS?` → `46001`）发 `10000`（电信客服）必报 `+CMS ERROR: 313`，同一份代码发 `10010` 一次成功。判断口径：手工绕过 agent 直接跑厂商脚本，同样报错就是网络/运营商侧。
2. **失败后 120 秒禁重发**是上游保护（`previous SMS outcome unknown`），实测点完失败立刻再点会被拦，等两分钟即可；`send.json` 里 `sent:false` 就是未确认状态。
3. **`/api/sms` 短暂回 `[]`**：agent 重启后要等一轮 3 秒扫描，`analyze` 前先 `sleep 8` 再看，别当回归。
4. **二进制换了 md5 必须核对**：设备侧 `md5sum /usr/lib/airsim/airsim-agent` 不变化说明根本没换上去（`Text file busy` 会静默留在旧文件）。本轮旧 `7c53591a…` → 新 `c203188e91613c1cc191a9c58f9a1b6e`。
